cheat sheet

Syntax, built-ins, the buffers the engine hands you, the ones you build yourself, post-processing, compute and the Compositor, plus complete scripts you can paste into a project. Written for Godot 4.3+ (reversed-Z era) and checked against 4.7.

How a frame is drawn

Every shader you write runs at a specific moment in Godot's frame. Knowing the order tells you what data exists yet, which buffers you can read, and where a post-process can be inserted. This is the Forward+ order for one 3D viewport; Mobile is similar with fewer screen-space passes, Compatibility (OpenGL) has no Compositor and no compute.

  1. SubViewports render first

    Each SubViewport with its own camera runs this entire list before the main viewport, so its ViewportTexture is ready for the main scene to sample. This is how you build extra render targets.

  2. GPU particles simulate

    start() runs when a particle spawns, process() every frame. Collision heightfields/SDFs and attractors are applied here.

    particles
  3. Sky radiance and low-res sky passes

    The sky shader renders into the radiance cubemap (AT_CUBEMAP_PASS) that feeds reflections and ambient light, plus optional half/quarter resolution passes.

    sky
  4. Shadow maps

    Your spatial vertex() runs from each light's point of view (IN_SHADOW_PASS is true). Fragment only runs if needed for alpha scissor/hash.

    spatial vertex()
  5. Depth prepass and normal-roughness buffer

    Opaque geometry writes depth (and, in Forward+, view-space normals + roughness). This is what hint_depth_texture and hint_normal_roughness_texture read later.

    spatial
  6. CompositorEffect · EFFECT_CALLBACK_TYPE_PRE_OPAQUE
  7. Volumetric fog froxels

    FogVolume shaders inject density, albedo and emission into a 3D grid of camera-aligned cells. The result is applied while shading surfaces and sky.

    fog
  8. Opaque pass

    Spatial fragment() fills the material outputs, then light() runs once per light per pixel. SSAO, SSIL, SSR and SDFGI feed into this.

    spatial fragment() + light()
  9. CompositorEffect · EFFECT_CALLBACK_TYPE_POST_OPAQUE
  10. Sky background

    The sky shader's main pass fills every pixel no geometry covered.

    sky
  11. CompositorEffect · EFFECT_CALLBACK_TYPE_POST_SKY
  12. Screen and depth copy

    The opaque image and depth are copied so transparent shaders can sample them. This is why screen-reading shaders don't see other transparent objects.

  13. CompositorEffect · EFFECT_CALLBACK_TYPE_PRE_TRANSPARENT
  14. Transparent pass

    Anything that writes ALPHA, reads the screen texture, or uses a blend mode is sorted back to front and drawn. Stencil reads only work here.

    spatial (transparent)
  15. CompositorEffect · EFFECT_CALLBACK_TYPE_POST_TRANSPARENT (still linear HDR, before tonemap)
  16. Built-in post-processing

    Depth of field, glow/bloom, exposure, tonemapping, color adjustments/LUT, then FXAA/SMAA. Configure in Environment and CameraAttributes.

  17. 2D canvas and UI

    CanvasLayers draw in order on top of the 3D result. Canvas shaders can read everything drawn so far via the back buffer (hint_screen_texture). UI is just more canvas items.

    canvas_item

compute shaders are not in this list at all: you dispatch them yourself, either on a separate local GPU device or on the main device from the render thread (which is exactly what a CompositorEffect does at the hook points above).

Shader types at a glance

The first line of every .gdshader file picks the type. The type decides which processor functions exist, which built-ins you get, and where you can plug it in.

File extensions. .gdshader for shaders, .gdshaderinc for include files, .glsl for compute (imported as RDShaderFile). VisualShader resources (.tres) compile to the same language.

Shading language syntax

Godot's language is GLSL ES 3.0 with the boilerplate removed: no main(), no in/out declarations, no #version. You write processor functions and assign to UPPERCASE built-ins.

Buffers the engine gives you

You never bind these manually. Declare a uniform with the right hint (or read a built-in) and Godot wires it up. Each has a moment in the frame when it's valid.

What's available, where

Screen texture recipes

Things that surprise people. In 3D, the screen texture doesn't contain transparent objects (they're drawn after the copy), and objects that read it don't see each other. In 2D, the copy happens the first time a node reads it; drop a BackBufferCopy node between layers to force a fresh copy so a later effect sees an earlier one.

Depth: linearize and reconstruct positions

The depth buffer is non-linear. Multiply by the inverse projection to get real distances, then by the inverse view to get world positions. Custom functions can't see built-ins, so pass the matrices in.

SubViewport as a render target: selection-outline mask

This is the classic "custom G-buffer": a second camera sees only one render layer, draws those objects flat white into a SubViewport, and a full-screen shader reads that texture to draw an outline. The same pattern gives you minimaps, portals, security cameras, and water reflection passes.

Assigning ViewportTextures in the editor. Mark the material Local to Scene first, then choose New ViewportTexture on the uniform and pick the SubViewport. The outline above shows through walls because walls aren't on layer 2; put occluders on layer 2 with a black material if you want it hidden.

Feedback buffer: reading last frame

A SubViewport set to never clear keeps last frame's pixels. A full-size ColorRect drawn first inside it reads them through the screen texture, fades them, and the rest of the viewport draws on top. Result: motion trails, paint, or a simple cellular simulation.

Precision. An 8-bit target can't fade below about 1/255 × (1 − decay) per step, which leaves ghost smears. use_hdr_2d makes the viewport a half-float target and fixes it. For heavy simulations (fluids, reaction-diffusion) use the compute ping-pong pattern in the Compute section instead.

4. CompositorEffect

Compute shaders

Compute shaders are plain GLSL 4.50 run through RenderingDevice. No built-in variables, no materials: you create buffers and textures, bind them, and dispatch a grid of threads. Available on Forward+ and Mobile, not Compatibility.

Threads, workgroups, dispatch

You pick a workgroup size in the shader (local_size_x/y/z) and the number of workgroups when you dispatch. Total threads = workgroups × local size. Round up and guard against overshoot.

The #[compute] line tells Godot's importer this .glsl is a compute shader. It's imported as an RDShaderFile; compile errors appear when you select the file in the FileSystem dock. #include "other.glsl" works relative to the file.

Game of Life on the main device. Two textures swap roles every step (read A write B, then read B write A). A Texture2DRD lets a normal Sprite2D display whichever is current, so any material, mesh or UI can use it too. Hold the left mouse button to paint.

The Compositor 4.3+

A CompositorEffect is a resource with a _render_callback that Godot calls at one of five points in the 3D frame, handing you the live render buffers. You run compute shaders on them. Everything is still linear HDR, so tonemapping and glow happen after you.

Setup

  1. Write a script that extends CompositorEffect with @tool (so it previews in the editor) and a class_name.
  2. Select your WorldEnvironment (applies to every camera) or a Camera3D (overrides for that camera). Set Compositor → New Compositor.
  3. In Compositor Effects, add an element and choose your class. Order in the array is execution order for the same callback.

Gotchas, debugging, performance

Symptom → cause → fix

Debugging techniques

  • Visualise the value. ALBEDO = vec3(fract(x)); or COLOR = vec4(vec3(v), 1.0);. For signed values: vec3(v * 0.5 + 0.5). Use render_mode unshaded while doing it so lighting doesn't hide the value.
  • Editor debug draws. 3D viewport → Perspective menu → Display Advanced: Normal Buffer, SSAO, Directional Shadow Splits, Overdraw, Unshaded and more.
  • GPU timings. Debugger → Visual Profiler shows GPU time per render pass, including your compositor effects.
  • Frame capture. Launch the game from RenderDoc to inspect every draw and compute dispatch, bound textures and push constants. Start Godot with --gpu-validation to get Vulkan validation messages for RenderingDevice mistakes.
  • Generated code. Convert any built-in material to a ShaderMaterial to see how Godot itself writes the effect.

Performance habits

  • Move maths from fragment() to vertex() and pass it through a varying when it varies slowly across a triangle.
  • discard and ALPHA_SCISSOR_THRESHOLD are cheaper than true transparency, but still defeat some early-depth optimisations; keep cut-out areas small.
  • Writing ALPHA, reading the screen texture, or using blend modes forces sorting and overdraw. Use opaque whenever possible.
  • Screen-space loops (blurs, outlines) cost texture reads per pixel. Use mipmaps with textureLod, separable passes in compute, or render at lower resolution.
  • For sky shaders, put expensive work in the half/quarter-res passes and skip detail when AT_CUBEMAP_PASS is true. Set the Sky's Process Mode to Incremental or Real-Time only if the sky changes.
  • Prefer MODELVIEW_MATRIX over VIEW_MATRIX * MODEL_MATRIX for precision far from the origin, and avoid inverse() per vertex when a uniform can hold the precomputed matrix.
  • Compute: 64 threads per workgroup is a safe default; reuse uniform sets (UniformSetCacheRD); keep data on the GPU and avoid readbacks in the frame loop.
