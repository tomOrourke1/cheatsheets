One window, one vertex buffer, one draw call. Your own data goes up to the GPU — position and colour per vertex — and every line below is a place something bigger plugs in.

BackendMetal (native) Shader languageWGSL Rust MSRV1.87 Vertex stride24 bytes Total lines~160

wgpu asks you to build the whole graphics state up front and hand it over frozen. That feels like a lot of ceremony for one triangle, but it is the same ceremony for a full renderer — nothing here gets thrown away later.

Read it as a chain. Each object can only be made once the one before it exists, and the last two links repeat every frame. The highlighted links are the data path: a Rust struct becomes bytes, bytes become a buffer, and a layout tells the GPU how to read them back.

00

The event loop

winit owns main(); your renderer is a guest

src/main.rs — top

use std::sync::Arc;
use wgpu::util::DeviceExt;          // brings create_buffer_init() into scope
use winit::application::ApplicationHandler;
use winit::event::{KeyEvent, WindowEvent};
use winit::event_loop::{ActiveEventLoop, EventLoop};
use winit::keyboard::{KeyCode, PhysicalKey};
use winit::window::{Window, WindowId};

fn main() -> anyhow::Result<()> {
    env_logger::init();
    let event_loop = EventLoop::new()?;
    let mut app = App { state: None };
    event_loop.run_app(&mut app)?;
    Ok(())
}

struct App { state: Option<State> }

impl ApplicationHandler for App {
    // Called once the platform is ready to give you a window.
    fn resumed(&mut self, event_loop: &ActiveEventLoop) {
        if self.state.is_some() { return; }
        let attrs = Window::default_attributes()
            .with_title("hello triangle");
        let window = Arc::new(event_loop.create_window(attrs).unwrap());
        self.state = Some(pollster::block_on(State::new(window)).unwrap());
    }

    fn window_event(
        &mut self,
        event_loop: &ActiveEventLoop,
        _id: WindowId,
        event: WindowEvent,
    ) {
        let Some(state) = self.state.as_mut() else { return };
        match event {
            WindowEvent::CloseRequested => event_loop.exit(),
            WindowEvent::Resized(size) => state.resize(size.width, size.height),
            WindowEvent::RedrawRequested => state.render(),
            WindowEvent::KeyboardInput {
                event: KeyEvent {
                    physical_key: PhysicalKey::Code(KeyCode::Escape), ..
                }, ..
            } => event_loop.exit(),
            _ => {}
        }
    }
}

Since winit 0.30 the loop is a trait, not a closure. You implement ApplicationHandler and winit calls you.

The window cannot exist before resumed(), so everything downstream of it is Option-shaped until then. That is why State is built inside resumed rather than in main.

Arc<Window>, not Window: the surface needs to hold a reference for its whole life. Handing wgpu an Arc lets it own one and gives you a Surface<'static>.

DeviceExt is an extension trait. Without that import, device.create_buffer_init(...) in stage 06 simply will not resolve.

extendsAdd about_to_wait() for a continuous render loop, device_event() for raw mouse deltas, and EventLoop::with_user_event() when you need to wake the loop from another thread.

01

Instance

which backends this process is allowed to use

src/main.rs — State::new()

struct State {
    window:   Arc<Window>,
    surface:  wgpu::Surface<'static>,
    device:   wgpu::Device,
    queue:    wgpu::Queue,
    config:   wgpu::SurfaceConfiguration,
    configured: bool,
    pipeline: wgpu::RenderPipeline,
    vertex_buffer: wgpu::Buffer,
    vertex_count:  u32,
}

impl State {
    async fn new(window: Arc<Window>) -> anyhow::Result<Self> {
        let size = window.inner_size();   // PHYSICAL pixels

        let instance = wgpu::Instance::new(wgpu::InstanceDescriptor {
            backends: wgpu::Backends::METAL,
            ..wgpu::InstanceDescriptor::new_without_display_handle()
        });

The instance does nothing but hand out adapters and surfaces. It does not need to be kept alive afterwards.

Backends::METAL is the honest choice on macOS. Backends::PRIMARY is the portable one — same code, also picks Vulkan and DX12 elsewhere.

size is in physical pixels already. On a Retina display an 800×600 logical window reports 1600×1200 here, and that is exactly what the surface wants. Do not divide by scale_factor().

extendsInstanceFlags::debugging() in the flags field turns on validation and API labels. Backends::from_env() lets WGPU_BACKEND=… override the choice at runtime.

02

Surface

the piece of the window you are allowed to draw into

src/main.rs — State::new()

        let surface = instance.create_surface(window.clone())?;

One line, but it is the bridge between two crates: winit's Window implements raw-window-handle, and that is all wgpu asks for.

Cloning the Arc transfers an owner into the surface, so the window outlives every frame that references it.

macOSMetal surface creation panics if it is not on the main thread. Since resumed() runs on the main thread, keeping State::new there is the whole fix.

03

Adapter

a physical GPU, picked to match the surface

src/main.rs — State::new()

        let adapter = instance
            .request_adapter(&wgpu::RequestAdapterOptions {
                power_preference: wgpu::PowerPreference::default(),
                compatible_surface: Some(&surface),
                force_fallback_adapter: false,
                apply_limit_buckets: false,
            })
            .await?;

Passing compatible_surface is what guarantees the GPU you get can actually present to this window. On an Intel Mac with two GPUs this is the difference between a picture and a validation error.

power_preference is a hint: LowPower favours the integrated GPU and battery life, HighPerformance the discrete one.

apply_limit_buckets rounds the reported limits into coarse tiers, which hides the exact hardware from fingerprinting and makes per-tier shader caching possible. Off is fine while you are learning.

extendsadapter.get_info() for the device name and backend, adapter.features() and adapter.limits() before you ask for anything unusual in stage 04.

04

Device and Queue

the logical GPU, plus the pipe you push work and data down

src/main.rs — State::new()

        let (device, queue) = adapter
            .request_device(&wgpu::DeviceDescriptor {
                label: Some("device"),
                required_features: wgpu::Features::empty(),
                required_limits:   wgpu::Limits::default(),
                experimental_features: wgpu::ExperimentalFeatures::disabled(),
                memory_hints: wgpu::MemoryHints::default(),
                trace: wgpu::Trace::Off,
            })
            .await?;

Device creates resources — buffers, textures, pipelines. Queue submits work and writes into buffers after the fact. Both are cheap to clone and are Send + Sync.

What you ask for here is what you get — exactly. Request no features and using one later is a validation error, not a silent success. Request Limits::default() and your app stays portable down to WebGPU-class hardware.

extendsrequired_features is where POLYGON_MODE_LINE, timestamp queries and native-only extras get switched on, gated by what adapter.features() reported. Trace::Directory(path) records an API trace for bug reports.

05

Configure the surface

format, size, and how frames reach the display

src/main.rs — State::new()

        let caps = surface.get_capabilities(&adapter);
        let format = caps.formats.iter().copied()
            .find(|f| f.is_srgb())
            .unwrap_or(caps.formats[0]);

        let config = wgpu::SurfaceConfiguration {
            usage:  wgpu::TextureUsages::RENDER_ATTACHMENT,
            format,
            color_space: wgpu::SurfaceColorSpace::Auto,
            width:  size.width,
            height: size.height,
            present_mode: wgpu::PresentMode::Fifo,   // vsync, always supported
            desired_maximum_frame_latency: 2,
            alpha_mode: caps.alpha_modes[0],
            view_formats: vec![],
        };
        // configure() itself happens in resize(), below.

Preferring an *Srgb format means the hardware does the sRGB encode on write, so your shader — and therefore your vertex colours — work in linear light and still look right.

Fifo is vsync and is guaranteed on every platform. AutoNoVsync is the "uncapped, fall back gracefully" option.

desired_maximum_frame_latency trades latency against smoothness: 1 is the most responsive, 2 the default compromise.

extendscolor_space is the door to HDR and wide gamut — read caps.format_capabilities, pick something other than Auto, and take over tone mapping yourself.

06

Your data → a Buffer

a Rust struct, some bytes, and a promise about how to read them

src/main.rs — above State

#[repr(C)]                                    // C field order, no reordering
#[derive(Copy, Clone, Debug, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {
    position: [f32; 3],    // clip space: x, y in -1..1, +y up
    color:    [f32; 3],    // LINEAR rgb, not sRGB
}

impl Vertex {
    // A const, so the attribute array is not a temporary.
    const LAYOUT: wgpu::VertexBufferLayout<'static> = wgpu::VertexBufferLayout {
        array_stride: std::mem::size_of::<Self>() as wgpu::BufferAddress,  // 24
        step_mode: wgpu::VertexStepMode::Vertex,     // advance once per vertex
        attributes: &wgpu::vertex_attr_array![
            0 => Float32x3,     // byte 0..12  -> @location(0) position
            1 => Float32x3,     // byte 12..24 -> @location(1) color
        ],
    };
}

// Counter-clockwise: top, bottom-left, bottom-right.
const VERTICES: &[Vertex] = &[
    Vertex { position: [ 0.0,  0.55, 0.0], color: [1.0, 0.0, 0.0] },
    Vertex { position: [-0.6, -0.45, 0.0], color: [0.0, 1.0, 0.0] },
    Vertex { position: [ 0.6, -0.45, 0.0], color: [0.0, 0.0, 1.0] },
];

src/main.rs — State::new()

        let vertex_buffer = device.create_buffer_init(
            &wgpu::util::BufferInitDescriptor {
                label: Some("vertices"),
                contents: bytemuck::cast_slice(VERTICES),   // -> &[u8]
                usage: wgpu::BufferUsages::VERTEX,
            }
        );
        let vertex_count = VERTICES.len() as u32;

#[repr(C)] is not decoration. Without it Rust may reorder fields, and your byte offsets stop matching the layout you just declared.

Pod ("plain old data") and Zeroable are what let bytemuck::cast_slice reinterpret &[Vertex] as &[u8] safely. Derive them; do not hand-write the unsafe impl unless a field forces you to.

create_buffer_init allocates and uploads in one call — ideal for data that never changes. It comes from the DeviceExt trait imported in stage 00.

vertex_attr_array! computes offsets for you from the format list, so adding a field means editing one line rather than three.

Colours here are linear. Pure 1.0 and 0.0 come out unchanged, but a midtone will not: 0.5 reaches the screen as roughly #BC, not #80.

extendsAdd | BufferUsages::COPY_DST and you can overwrite it later with queue.write_buffer(). Add fields — UVs, normals — by extending the struct and the vertex_attr_array! list together. Add a second buffer with step_mode: Instance for per-instance transforms.

07

Shader module

WGSL in, Metal shading language out, courtesy of naga

src/shader.wgsl

// Matches Vertex::LAYOUT. These locations are vertex ATTRIBUTE slots.
struct VertexIn {
    @location(0) position: vec3f,
    @location(1) color:    vec3f,
}

// These locations are INTERPOLATOR slots between the two stages.
// The numbering restarts; @location(0) here is unrelated to the one above.
struct VertexOut {
    @builtin(position) clip_position: vec4f,
    @location(0) color: vec3f,
}

@vertex
fn vs_main(v: VertexIn) -> VertexOut {
    var out: VertexOut;
    out.clip_position = vec4f(v.position, 1.0);
    out.color = v.color;
    return out;
}

@fragment
fn fs_main(in: VertexOut) -> @location(0) vec4f {
    // in.color has been interpolated across the triangle for us.
    return vec4f(in.color, 1.0);
}

src/main.rs — State::new()

        let shader = device.create_shader_module(
            wgpu::include_wgsl!("shader.wgsl")
        );

The vertex shader runs once per vertex, the fragment shader once per pixel covered. Anything you put in VertexOut beyond @builtin(position) gets interpolated between the three corners on the way — that interpolation is the entire reason the triangle is a gradient and not three flat colours.

@builtin(position) is clip space: x and y run −1..1 with +y up, and the GPU divides by w afterwards. Passing 1.0 as w means no perspective divide.

vec3f and vec4f are the short aliases for vec3<f32> and vec4<f32>.

include_wgsl! embeds the file at compile time. Swap it for ShaderSource::Wgsl(string.into()) to load and recompile shaders at runtime.

extendsAdd @location(1) uv: vec2f to both structs to carry texture coordinates. Multiply clip_position by a matrix from a uniform to get a camera. The same file can hold a @compute entry point too.

08

Pipeline layout

the declaration of everything the shader reads that is not a vertex

src/main.rs — State::new()

        let layout = device.create_pipeline_layout(
            &wgpu::PipelineLayoutDescriptor {
                label: Some("layout"),
                bind_group_layouts: &[],   // no uniforms, textures or samplers
                immediate_size: 0,          // no small per-draw constants
            }
        );

Vertex buffers do not go here — they are described on the pipeline itself in stage 09. This is for the other channel: uniforms, textures, samplers, storage buffers.

Empty is still meaningful. Every uniform buffer and texture you ever add gets declared in this one place first.

immediate_size is the successor to push constants — a tiny block of bytes set per draw, without a buffer.

extendsCreate a BindGroupLayout, list it here as &[Some(&bgl)], then build matching BindGroups and bind them per draw in stage 10. Slots may be None, so different pipelines can keep the same group indices.

09

Render pipeline

the whole fixed-function state, compiled once and frozen

src/main.rs — State::new()

        let pipeline = device.create_render_pipeline(
            &wgpu::RenderPipelineDescriptor {
                label: Some("triangle"),
                layout: Some(&layout),

                vertex: wgpu::VertexState {
                    module: &shader,
                    entry_point: Some("vs_main"),
                    buffers: &[Some(Vertex::LAYOUT)],   // slot 0
                    compilation_options: Default::default(),
                },

                fragment: Some(wgpu::FragmentState {
                    module: &shader,
                    entry_point: Some("fs_main"),
                    targets: &[Some(wgpu::ColorTargetState {
                        format: config.format,   // must match the surface
                        blend: Some(wgpu::BlendState::REPLACE),
                        write_mask: wgpu::ColorWrites::ALL,
                    })],
                    compilation_options: Default::default(),
                }),

                primitive: wgpu::PrimitiveState {
                    topology: wgpu::PrimitiveTopology::TriangleList,
                    front_face: wgpu::FrontFace::Ccw,
                    cull_mode: Some(wgpu::Face::Back),
                    ..Default::default()
                },

                depth_stencil: None,
                multisample: wgpu::MultisampleState::default(),
                multiview_mask: None,
                cache: None,
            }
        );

        Ok(Self {
            window, surface, device, queue, config,
            configured: false, pipeline, vertex_buffer, vertex_count,
        })
    }

buffers is the index of this list mapping to vertex buffer slots. Since wgpu 30 it is &[Option<VertexBufferLayout>], so you can leave a slot None and keep, say, instance data at slot 2 across pipelines that differ at slot 1.

Everything a draw call needs, except the data itself, decided in advance. Changing any of it means building another pipeline — which is why real renderers build a handful up front and switch between them.

targets[0].format has to equal the surface format from stage 05. Mismatch is the most common validation error at startup.

Winding and culling are a matched pair: v0→v1→v2 is counter-clockwise, so Ccw + cull Back keeps the triangle. Flip either and it disappears silently.

extendsblend takes ALPHA_BLENDING for transparency. depth_stencil takes a depth format. multisample.count = 4 plus a resolve target gives MSAA. targets can hold several entries for deferred rendering.

10

Resize and frame

the only two functions that run more than once

src/main.rs — impl State (continued)

    fn resize(&mut self, width: u32, height: u32) {
        if width == 0 || height == 0 { return; }   // minimised
        self.config.width  = width;
        self.config.height = height;
        self.surface.configure(&self.device, &self.config);
        self.configured = true;
    }

    fn render(&mut self) {
        self.window.request_redraw();           // ask for the next frame
        if !self.configured { return; }

        let frame = match self.surface.get_current_texture() {
            wgpu::CurrentSurfaceTexture::Success(t)
            | wgpu::CurrentSurfaceTexture::Suboptimal(t) => t,
            wgpu::CurrentSurfaceTexture::Outdated => {
                self.surface.configure(&self.device, &self.config);
                return;
            }
            _ => return,   // Timeout | Occluded | Validation | Lost
        };

        let view = frame.texture.create_view(&Default::default());
        let mut encoder = self.device
            .create_command_encoder(&Default::default());

        {
            let mut pass = encoder.begin_render_pass(
                &wgpu::RenderPassDescriptor {
                    label: Some("clear + draw"),
                    color_attachments: &[Some(wgpu::RenderPassColorAttachment {
                        view: &view,
                        resolve_target: None,
                        depth_slice: None,
                        ops: wgpu::Operations {
                            load: wgpu::LoadOp::Clear(wgpu::Color {
                                r: 0.1, g: 0.2, b: 0.3, a: 1.0,
                            }),
                            store: wgpu::StoreOp::Store,
                        },
                    })],
                    depth_stencil_attachment: None,
                    timestamp_writes: None,
                    occlusion_query_set: None,
                    multiview_mask: None,
                }
            );

            pass.set_pipeline(&self.pipeline);
            pass.set_vertex_buffer(0, self.vertex_buffer.slice(..));
            pass.draw(0..self.vertex_count, 0..1);   // 3 vertices, 1 instance
        }                              // pass dropped -> encoder free again

        self.queue.submit([encoder.finish()]);
        self.queue.present(frame);
    }
}

set_vertex_buffer(0, ..) binds to slot 0 — the same slot index as position 0 in the pipeline's buffers list. slice(..) is the whole buffer; a range lets one buffer hold several meshes.

draw(0..3, 0..1) is a vertex range and an instance range. The vertex range indexes into the bound buffer, so it must not exceed what you uploaded.

request_redraw() first, unconditionally: winit only draws once unless you keep asking, and putting it at the top means an early return still schedules the next frame.

The configured flag exists because the first Resized event arrives after resumed(). Draw before it and you hit a validation error.

get_current_texture() returns an enum, not a Result. Outdated means the window changed underneath you — reconfigure and skip a frame. Everything else is a skip.

extendsset_index_buffer() + draw_indexed() to stop repeating shared vertices. set_bind_group() for uniforms. queue.write_buffer() before submit to animate the data. draw(0..3, 0..1000) for instancing.

macOS notes

what is different when Metal is the backend

Nothing to install

The Metal backend is compiled in by default and links against the system framework. No Vulkan SDK, no MoltenVK, no shader toolchain. cargo run is the whole setup.

Main thread only

Both EventLoop::new() and Metal surface creation must happen on the main thread. Build State inside resumed() and this never comes up.

Retina is already handled

inner_size() is physical pixels — 2× the logical size on a Retina panel. Feed it straight to the surface config. Dragging between displays fires ScaleFactorChanged then Resized; handling Resized covers both.

Live resize

macOS runs a nested loop while you drag a window edge. You get Resized and RedrawRequested in pairs, and the image can look stretched between them. Reconfiguring in resize() before drawing is what keeps it clean.

Debugging

RUST_LOG=wgpu_core=info,wgpu_hal=info cargo run for the real errors. MTL_CAPTURE_ENABLED=1 lets Xcode's GPU frame capture attach — which is also how you inspect what is actually in your vertex buffer.

The colour you actually see

Everything you write is linear. LoadOp::Clear(0.1, 0.2, 0.3) reaches the display as roughly #597C95, and a vertex colour of 0.5 lands near #BC — noticeably lighter than the numbers suggest.

Where it breaks

roughly in the order people hit them

01

No env_logger::init()

wgpu panics with a generic message and logs the real error through the log crate. Without a logger installed, that error goes nowhere and you are debugging blind.

02

Drawing before the surface is configured

configure() happens on the first Resized, which arrives after resumed(). Guard render() with a flag, or call resize() once at the end of State::new.

03

Configuring a zero-sized surface

Minimising sends Resized(0, 0). Configuring with a zero dimension is a validation error and can take the process down. Return early.

04

Letting the window drop

A Surface<'a> borrows its window. Pass an Arc<Window> into create_surface so wgpu takes an owner and you get Surface<'static>; storing a bare Window next to the surface fights the borrow checker forever.

05

Vertex struct without #[repr(C)]

Rust's default layout is unspecified and the compiler may reorder or pad your fields. The offsets in vertex_attr_array! assume C layout, so without #[repr(C)] you get scrambled geometry or a bytemuck compile error about padding.

06

Missing DeviceExt import

create_buffer_init lives on an extension trait. Without use wgpu::util::DeviceExt; the method does not exist, and the error message points at Device rather than the missing import.

07

Locations that do not line up

shader_location in the layout must match @location(n) in VertexIn, and the VertexFormat must match the WGSL type — Float32x3 for vec3f. Get either wrong and pipeline creation fails with a shader-interface error.

08

Confusing the two kinds of @location

Locations on VertexIn name vertex attribute slots. Locations on VertexOut name interpolators between the vertex and fragment stages. They are separate numbering spaces that both start at 0.

09

Forgetting set_vertex_buffer

The pipeline declares slot 0, so the pass must fill slot 0 before the draw. Skipping it is a validation error, not an empty triangle.

10

Wrong buffer usage flags

BufferUsages::VERTEX is required to bind it as vertex data. Add COPY_DST only if you intend to write_buffer into it later — asking for usages you do not need costs you nothing but hides real mistakes.

11

Identical entry point names

The WGSL spec requires the vertex and fragment entry points to have different names. vs_main / fs_main is the convention; main / main fails to compile.

12

Winding fighting the cull mode

The triangle is counter-clockwise. With FrontFace::Ccw and cull_mode: Some(Face::Back) it survives. Reorder the vertices, or switch to Cw, and it is culled — no error, no triangle. Set cull_mode: None to rule this out while debugging.

13

Pipeline format vs surface format

ColorTargetState::format must equal SurfaceConfiguration::format. Hard-coding Bgra8UnormSrgb works until it does not; read it from the config.

14

Reconfiguring while a frame is alive

Surface::configure() panics if a SurfaceTexture from that surface has not been dropped or presented yet. Finish the frame first, then reconfigure.

15

Forgetting to drop the render pass

begin_render_pass borrows the encoder mutably, so encoder.finish() will not compile until the pass is gone. Wrap it in a block or call drop(pass).

16

Presenting the old way

SurfaceTexture::present() was removed in wgpu 30. It is queue.present(frame) now, after queue.submit. Most tutorials older than mid-2026 still show the old call.
