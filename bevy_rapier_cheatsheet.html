Getting it in the project

cargo · features · first app

Add the dependency Cargo.toml

Pick one dimension per binary. The 2D and 3D crates export the same type names and will collide if you import both preludes.

# cargo add bevy_rapier2d --features debug-render-2d

[dependencies]
bevy = "0.19"
bevy_rapier2d = { version = "0.36", features = ["debug-render-2d"] }

# 3D instead:
# bevy_rapier3d = { version = "0.36", features = ["debug-render-3d"] }

Smallest app that simulates main.rs

use bevy::prelude::*;
use bevy_rapier2d::prelude::*;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        // 100 px == 1 metre. In 3D use ::default() instead.
        .add_plugins(RapierPhysicsPlugin::<NoUserData>::pixels_per_meter(100.0))
        .add_plugins(RapierDebugRenderPlugin::default())
        .add_systems(Startup, setup)
        .run();
}

fn setup(mut commands: Commands) {
    commands.spawn(Camera2d);

    // Ground: a collider with no RigidBody is implicitly static.
    commands.spawn((
        Collider::cuboid(500.0, 20.0),
        Transform::from_xyz(0.0, -180.0, 0.0),
    ));

    // A ball that falls onto it.
    commands.spawn((
        RigidBody::Dynamic,
        Collider::ball(24.0),
        Restitution::coefficient(0.75),
        Transform::from_xyz(0.0, 300.0, 0.0),
    ));
}

The mental model

four nouns, one loop

Four nouns

  • RigidBody — has mass, velocity, and a position the solver owns. Optional.
  • Collider — a shape that occupies space. Attaches to a body, or stands alone as static level geometry.
  • Sensor — a collider that reports overlaps but never pushes.
  • Joint — a constraint between two bodies.

A collider with no body is static world geometry. A body with no collider is a mass point that nothing can touch — usually a mistake.

Where things live entity layout

Put both on one entity for the common case. Use children when one body needs several shapes, or when a shape needs an offset from the centre of mass.

// Single shape — one entity.
commands.spawn((RigidBody::Dynamic, Collider::capsule_y(20.0, 10.0)));

// Compound body — child transforms position each shape.
commands.spawn((RigidBody::Dynamic, Transform::default()))
    .with_children(|b| {
        b.spawn((Collider::cuboid(30.0, 8.0), Transform::from_xyz(0.0, 40.0, 0.0)));
        b.spawn((Collider::ball(14.0),        Transform::from_xyz(0.0, 0.0,  0.0)));
    });

The frame loop who writes Transform, and when

The plugin runs in PostUpdate by default, in three ordered sets:

  • PhysicsSet::SyncBackend — your component edits are copied into rapier.
  • PhysicsSet::StepSimulation — the solver advances and emits collision messages.
  • PhysicsSet::Writeback — rapier's results are written back into Transform.

So: write to Velocity / ExternalForce during Update and they land in the next step. Read Transform during Update and you get last frame's result — fine for almost everything.

// Run physics on the fixed timestep instead of PostUpdate:
RapierPhysicsPlugin::<NoUserData>::default().in_fixed_schedule()

// Or any schedule you like:
RapierPhysicsPlugin::<NoUserData>::default().in_schedule(MyPhysicsSchedule)

// Order your own system against a physics set:
app.add_systems(PostUpdate, my_camera_follow.after(PhysicsSet::Writeback));

Reaching the world ReadRapierContext / WriteRapierContext

Every raycast, overlap test, and contact lookup goes through the context. Since 0.29 it is four components on a context entity, and these two SystemParams bundle them for you. single() returns a Result.

use bevy_rapier2d::prelude::*;

fn my_system(rapier: ReadRapierContext) {
    let Ok(ctx) = rapier.single() else { return };

    // ctx.simulation     — broad phase, narrow phase, solver state
    // ctx.colliders      — collider set + entity lookup
    // ctx.joints         — impulse + multibody joint sets
    // ctx.rigidbody_set  — body set + entity lookup

    if let Some((entity, toi)) = ctx.cast_ray(
        Vec2::ZERO, Vec2::X, 400.0, true, QueryFilter::default(),
    ) {
        info!("hit {entity} at {toi}");
    }
}

// Need to mutate the world (teleport a body, run move_shape)? Use the write side:
fn mutating(mut rapier: WriteRapierContext) {
    let Ok(mut ctx) = rapier.single_mut() else { return };
    ctx.propagate_modified_body_positions_to_colliders();
}

Rigid bodies

motion, forces, constraints on motion

The four body types

VariantMoved byUse for
RigidBody::DynamicForces, impulses, contacts, gravityAnything that should behave like a physical object
RigidBody::FixedNothing. Infinite mass.Walls, floors, immovable props
RigidBody::KinematicPositionBasedYou, by writing TransformPlayer characters, elevators, doors following a path
RigidBody::KinematicVelocityBasedYou, by writing VelocityConveyors, constant-speed platforms

Kinematic bodies push, they never get pushed. A dynamic crate resting on a kinematic lift rides up. The lift does not slow down. That is the point — and the reason a kinematic body can crush a dynamic one into a wall.

Velocity renamed fields — 0.34+

// 2D: angular is a scalar (radians/sec around Z).
commands.spawn((
    RigidBody::Dynamic,
    Collider::ball(10.0),
    Velocity { linear: Vec2::new(120.0, 0.0), angular: 0.4 },
));

// 3D: angular is a Vec3.
Velocity { linear: Vec3::new(0.0, 5.0, 0.0), angular: Vec3::Y * 2.0 }

fn steer(mut q: Query<&mut Velocity, With<Player>>) {
    for mut v in &mut q {
        v.linear.x = 250.0;   // was v.linvel.x before 0.34
        v.angular = 0.0;      // was v.angvel
    }
}

// Velocity at an arbitrary world point on the body:
let v_at = velocity.linear_velocity_at_point(hit_point, center_of_mass);

Forces vs impulses

Force = continuous push, applied every step while present. Impulse = instant change in momentum, consumed once.

// Spawn with either:
commands.spawn((
    RigidBody::Dynamic,
    Collider::ball(8.0),
    ExternalForce  { force: Vec2::new(0.0, 900.0), torque: 0.0 },
    ExternalImpulse{ impulse: Vec2::new(60.0, 0.0), torque_impulse: 0.0 },
));

fn jump(mut q: Query<&mut ExternalImpulse, With<Player>>) {
    for mut imp in &mut q {
        imp.impulse = Vec2::new(0.0, 400.0);   // reset to zero automatically
    }
}

// Off-centre application (produces torque for free):
let mut f = ExternalForce::default();
f += ExternalForce::at_point(Vec2::new(0.0, 500.0), hit_point, center_of_mass);

ExternalImpulse clears itself after each step. ExternalForce does not — set it back to zero yourself or the body accelerates forever.

Motion modifiers

// Air resistance / spin decay.
Damping { linear_damping: 0.5, angular_damping: 1.0 }

// Per-body gravity multiplier. 0.0 = floats, 2.0 = heavy, -1.0 = falls up.
GravityScale(0.0)

// Freeze axes. 2D flags: TRANSLATION_LOCKED_X/_Y, ROTATION_LOCKED.
LockedAxes::ROTATION_LOCKED                       // upright character
LockedAxes::TRANSLATION_LOCKED_X | LockedAxes::ROTATION_LOCKED

// Continuous collision detection — for fast, thin, or small things.
Ccd::enabled()
SoftCcd { prediction: 10.0 }   // cheaper, less strict alternative

// Sleeping: bodies below the threshold stop being simulated.
Sleeping::disabled()

// Dominance: higher group is never pushed by lower. -127..=127.
Dominance::group(10)

// Extra solver passes for this body and everything it touches.
AdditionalSolverIterations(4)

Mass properties three ways to get them wrong

Mass comes from the collider's density by default. Adding ColliderMassProperties replaces that computation; adding AdditionalMassProperties adds on top of it.

// Replace: derive inertia from this shape at this density (the default, density 1.0).
ColliderMassProperties::Density(2.5)

// Replace: pin the mass, let the shape decide the inertia tensor.
ColliderMassProperties::Mass(80.0)

// Replace: specify everything by hand.
ColliderMassProperties::MassProperties(MassProperties {
    local_center_of_mass: Vec2::new(0.0, -10.0),
    mass: 80.0,
    principal_inertia: 400.0,       // Vec3 + principal_inertia_local_frame in 3D
})

// Add on top of the shape-derived mass (e.g. cargo in a truck).
AdditionalMassProperties::Mass(20.0)

// Read the result — this is a component the plugin keeps updated.
fn report(q: Query<&ReadMassProperties>) {
    for mp in &q { info!("{} kg", mp.mass); }
}

MassProperties is not a component. Inserting it does nothing. Use ColliderMassProperties or AdditionalMassProperties.

Turning bodies off

Cheaper than despawn-and-respawn, and it keeps the entity's other components intact.

commands.entity(e).insert(RigidBodyDisabled);   // frozen, ignored by solver
commands.entity(e).insert(ColliderDisabled);    // shape stops colliding

commands.entity(e).remove::<RigidBodyDisabled>();

// Pause the entire simulation instead:
fn pause(mut cfg: Query<&mut RapierConfiguration>) {
    for mut c in &mut cfg { c.physics_pipeline_active = false; }
}

Colliders

shapes, surfaces, sensors

Shape constructors 0.34+ takes glam vectors — no .into()

// ---- 2D ----------------------------------------------------------
Collider::ball(radius)
Collider::cuboid(half_x, half_y)                  // HALF extents, not full size
Collider::round_cuboid(half_x, half_y, border_radius)
Collider::capsule(Vec2::new(0.0, -20.0), Vec2::new(0.0, 20.0), 10.0)
Collider::capsule_y(half_height, radius)          // vertical, centred
Collider::capsule_x(half_height, radius)
Collider::segment(Vec2::ZERO, Vec2::new(100.0, 0.0))
Collider::triangle(a, b, c)
Collider::polyline(points, None)                  // open or closed line strip
Collider::convex_hull(&points)                    // -> Option<Collider>
Collider::convex_decomposition(&verts, &indices)  // concave, expensive to build
Collider::heightfield(heights, scale)
Collider::compound(vec![(pos, rot, shape), ..])

// ---- 3D ----------------------------------------------------------
Collider::cuboid(hx, hy, hz)
Collider::cylinder(half_height, radius)
Collider::cone(half_height, radius)
Collider::capsule_y(half_height, radius)
Collider::trimesh(vertices, indices)              // -> Result<Collider, _>
Collider::trimesh_with_flags(v, i, TriMeshFlags::MERGE_DUPLICATE_VERTICES)

Cuboids take half-extents. A 64×64 sprite wants Collider::cuboid(32.0, 32.0).

Trimeshes are hollow surfaces, not solids. A dynamic body should use convex_hull or convex_decomposition; reserve trimesh for static level geometry.

Surface properties

Friction {
    coefficient: 0.9,
    combine_rule: CoefficientCombineRule::Multiply,
}
Restitution::coefficient(0.9)     // 0 = dead thud, 1 = perfect bounce

// Combine rules decide how two touching colliders merge their values:
//   Average (default) · Min · Multiply · Max
// Frictionless ice next to grippy rubber?
//   Min      -> ice wins
//   Max      -> rubber wins

// A thin skin that starts resolving contact before shapes overlap.
// Kills jitter on fast, small, or stacked bodies.
ContactSkin(0.5)

Sensors triggers, zones, pickups

A sensor detects overlap and applies no force. It still needs ActiveEvents if you want messages from it.

commands.spawn((
    Collider::cuboid(60.0, 60.0),
    Sensor,
    ActiveEvents::COLLISION_EVENTS,
    Transform::from_xyz(0.0, 0.0, 0.0),
));

// Overlap events arrive with the SENSOR flag set:
CollisionEvent::Started(a, b, CollisionEventFlags::SENSOR)

Sensor ↔ sensor produces nothing. At least one side of the pair must be a solid collider.

Scaling & offsets

Collider shapes follow Transform scale automatically, including scale inherited from a parent. Non-uniform scale on a ball is approximated by a polygon — scaled_shape_subdivision controls how finely.

// Extra scale on top of the transform:
ColliderScale::Absolute(Vec2::new(2.0, 1.0))
ColliderScale::Relative(Vec2::new(2.0, 1.0))

// Offset a shape from the body origin: put it on a child with a Transform.
// A collider's own Transform rotation IS respected by the solver.

Collision events

the push-based half of collision checks

Opt in, then read 0.32+ uses MessageReader

Events are off by default for performance. A collider only reports if it carries ActiveEvents. Only one of the two colliders needs the flag.

use bevy_rapier2d::prelude::*;

commands.spawn((
    RigidBody::Dynamic,
    Collider::ball(12.0),
    ActiveEvents::COLLISION_EVENTS,        // start/stop touching
    // ActiveEvents::CONTACT_FORCE_EVENTS  // force magnitude reports
));

fn on_collision(
    mut collisions: MessageReader<CollisionEvent>,   // EventReader before 0.32
    players: Query<&Player>,
) {
    for ev in collisions.read() {
        match ev {
            CollisionEvent::Started(a, b, flags) => {
                if flags.contains(CollisionEventFlags::SENSOR) {
                    info!("{a} entered trigger {b}");
                } else if players.get(*a).is_ok() {
                    info!("player {a} hit {b}");
                }
            }
            CollisionEvent::Stopped(a, b, _) => info!("{a} left {b}"),
        }
    }
}

Order is not guaranteed. The entity you care about can be in either slot. Always test both, or write a helper that returns (mine, theirs).

Impact strength ContactForceEvent

Fires when the summed contact force between a pair exceeds a threshold. This is how you tell a gentle landing from a fall that should hurt.

commands.spawn((
    RigidBody::Dynamic,
    Collider::ball(12.0),
    ActiveEvents::CONTACT_FORCE_EVENTS,
    ContactForceEventThreshold(600.0),
));

fn damage(mut forces: MessageReader<ContactForceEvent>) {
    for ev in forces.read() {
        // ev.collider1, ev.collider2
        // ev.total_force        : Vec2 / Vec3
        // ev.total_force_magnitude : f32
        // ev.max_force_direction, ev.max_force_magnitude
        let hp = (ev.total_force_magnitude / 100.0) as u32;
        info!("{} took {hp} damage", ev.collider1);
    }
}

Which pairs generate events

By default only pairs involving a dynamic body are considered. Two kinematic bodies, or a kinematic body against static level geometry, are silently skipped.

// Default: DYNAMIC_DYNAMIC | DYNAMIC_KINEMATIC | DYNAMIC_FIXED

// A kinematic player that must detect static trigger volumes:
commands.spawn((
    RigidBody::KinematicPositionBased,
    Collider::capsule_y(20.0, 10.0),
    ActiveEvents::COLLISION_EVENTS,
    ActiveCollisionTypes::default() | ActiveCollisionTypes::KINEMATIC_FIXED,
));

// Full set: DYNAMIC_KINEMATIC, DYNAMIC_FIXED, KINEMATIC_KINEMATIC,
//           KINEMATIC_FIXED, FIXED_FIXED, DYNAMIC_DYNAMIC

The single most common "my trigger doesn't fire". Kinematic player + static sensor needs KINEMATIC_FIXED.

Pull instead of push CollidingEntities

A component that tracks the current touch set for you. Simpler than buffering messages when you only care about "am I touching X right now".

commands.spawn((
    Collider::cuboid(20.0, 20.0),
    ActiveEvents::COLLISION_EVENTS,   // still required
    CollidingEntities::default(),
));

fn check(q: Query<&CollidingEntities, With<Player>>, lava: Query<&Lava>) {
    for touching in &q {
        if touching.iter().any(|e| lava.get(e).is_ok()) {
            info!("standing in lava");
        }
    }
}

Contact data

asking the narrow phase directly

Four lookups on the context

Events tell you when something changed. These tell you what is true right now — call them any frame, no ActiveEvents needed.

fn inspect(rapier: ReadRapierContext, q: Query<Entity, With<Player>>) {
    let Ok(ctx) = rapier.single() else { return };
    let player = q.single().unwrap();

    // 1. Are these two specific solid colliders touching?
    if let Some(pair) = ctx.contact_pair(player, some_wall) {
        if pair.has_any_active_contact() { /* real, force-generating contact */ }
    }

    // 2. Everything currently touching this collider.
    for pair in ctx.contact_pairs_with(player) {
        let other = if pair.collider1() == Some(player) { pair.collider2() }
                    else { pair.collider1() };
        info!("touching {other:?}");
    }

    // 3. Is this specific sensor pair overlapping?
    if ctx.intersection_pair(player, goal_sensor) == Some(true) { /* inside */ }

    // 4. Every sensor overlap involving this collider.
    for (a, b, intersecting) in ctx.intersection_pairs_with(goal_sensor) {
        if intersecting { info!("{a} overlaps {b}"); }
    }
}

Solid pairs use contact_*; sensor pairs use intersection_*. A sensor will never show up in contact_pairs_with.

Digging into a contact manifolds, normals, impulses

A pair holds one or more manifolds (a flat region of contact); each manifold holds individual contact points. This is where you get the surface normal for a bounce, a decal, or a spark effect.

if let Some(pair) = ctx.contact_pair(a, b) {
    for manifold in pair.manifolds() {
        // Normals in the local frame of each collider:
        let n1 = manifold.local_n1();
        let n2 = manifold.local_n2();

        for contact in manifold.points() {
            let depth   = contact.dist();              // negative = penetrating
            let p1      = contact.local_p1();          // point on collider 1
            let impulse = contact.impulse();           // normal impulse applied
            let tangent = contact.tangent_impulse();   // friction impulse
        }

        // Post-solve view, includes friction/restitution actually used:
        for solver_contact in manifold.solver_contacts() {
            let world_point = solver_contact.point();
            let mu          = solver_contact.friction();
        }
    }
}

Scene queries

raycasts, overlaps, sweeps

Raycast the workhorse

fn shoot(rapier: ReadRapierContext) {
    let Ok(ctx) = rapier.single() else { return };

    let origin  = Vec2::new(0.0, 0.0);
    let dir     = Vec2::new(1.0, 0.0);   // need not be normalised, but should be
    let max_toi = 500.0;                 // in units of `dir` length
    let solid   = true;                  // true: a ray starting inside a shape hits at toi 0
    let filter  = QueryFilter::default();

    // Nearest hit, distance only.
    if let Some((entity, toi)) = ctx.cast_ray(origin, dir, max_toi, solid, filter) {
        let point = origin + dir * toi;
    }

    // Nearest hit with surface data.
    if let Some((entity, hit)) = ctx.cast_ray_and_get_normal(origin, dir, max_toi, solid, filter) {
        let point  = hit.point;
        let normal = hit.normal;
        let toi    = hit.time_of_impact;   // renamed from `toi` in 0.26
        let feature = hit.feature;         // which vertex/edge/face was struck
    }

    // EVERY hit along the ray. Return false from the callback to stop early.
    ctx.intersect_ray(origin, dir, max_toi, solid, filter, |entity, hit| {
        info!("pierced {entity} at {}", hit.time_of_impact);
        true      // keep going
    });
}

Point queries

// Everything containing this point (click-to-select, area damage centre).
ctx.intersect_point(world_pos, QueryFilter::default(), |entity| {
    info!("point is inside {entity}");
    true                      // false stops the search
});

// Nearest surface point on the nearest collider.
if let Some((entity, proj)) = ctx.project_point(
    world_pos, 200.0 /* max_dist */, true /* solid */, QueryFilter::default(),

    let closest = proj.point;
    let inside  = proj.is_inside;
}

Shape overlap

"What is inside this box / sphere right now" — explosions, melee arcs, spawn-point validation.

let blast = Collider::ball(150.0);

ctx.intersect_shape(
    epicentre,                       // shape_pos
    0.0,                             // shape_rot: f32 in 2D, Quat in 3D
    &*blast,                         // &dyn Shape — deref the Collider
    QueryFilter::default().exclude_sensors(),
    |entity| { damage(entity); true },
);

// Cheap and approximate — broad-phase AABBs only, no exact test.
// Great as a first pass before something expensive.
use bevy::math::bounding::Aabb2d;
ctx.intersect_aabb_conservative(
    Aabb2d { min: Vec2::new(-50.0, -50.0), max: Vec2::new(50.0, 50.0) },
    QueryFilter::default(),
    |entity| { candidates.push(entity); true },
);

Shape cast a thick raycast

Sweeps a shape along a vector and reports the first thing it would touch. Use it for ground checks with a real footprint, and for fast projectiles that a thin ray would slip past.

let shape = Collider::cuboid(14.0, 2.0);

let hit = ctx.cast_shape(
    start_pos,
    0.0,                             // shape rotation
    Vec2::NEG_Y * 40.0,              // shape velocity / sweep vector
    &*shape,
    ShapeCastOptions {
        max_time_of_impact: 1.0,     // fraction of the sweep vector
        target_distance: 0.0,        // stop this far short of contact
        stop_at_penetration: false,  // ignore shapes already overlapping at t=0
        compute_impact_geometry_on_penetration: true,
    },
    QueryFilter::default().exclude_collider(me),
);

if let Some((entity, h)) = hit {
    let toi    = h.time_of_impact;
    let status = h.status;   // Converged / Failed / PenetratingOrWithinTargetDist

    // Geometry lives behind `details`, and it is None when the shapes already
    // overlapped at t = 0 and compute_impact_geometry_on_penetration was false.
    if let Some(d) = h.details {
        let normal  = d.normal1;    // normal on the hit collider
        let contact = d.witness1;   // point on the hit collider
        let mine    = d.witness2;   // the matching point on the cast shape
    }
}

ShapeCastHit only carries time_of_impact and status directly. Reaching for hit.normal1 is the usual mistake — everything geometric sits inside hit.details: Option<ShapeCastHitDetails>.

Batching with_query_pipeline

Each shortcut method builds a scoped query pipeline internally. Firing hundreds of rays in one system? Build it once and reuse it.

fn many_rays(rapier: ReadRapierContext) {
    let Ok(ctx) = rapier.single() else { return };
    let filter = QueryFilter::default().exclude_sensors();

    let hits: Vec<_> = ctx.with_query_pipeline(filter, |pipeline| {
        (0..360).step_by(5).filter_map(|deg| {
            let a = (deg as f32).to_radians();
            let dir = Vec2::new(a.cos(), a.sin());
            pipeline.cast_ray(Vec2::ZERO, dir, 400.0, true)
        }).collect()
    });

    info!("{} rays connected", hits.len());
}

None of this works on a shape you haven't spawned. Every method here searches registered colliders. To test arbitrary shapes at arbitrary transforms — or to get a contact normal and penetration depth — drop below the ECS to Direct parry.

A ray fired from inside a body hits that body first. With solid = true it returns a hit at toi = 0. Exclude yourself, or start the ray outside your own shape.

Going direct to parry

shape maths with no bodies, no colliders, no simulation

What this is, and when you want it

Everything in Scene queries asks the same question: which registered colliders does this touch? It needs entities, a spawned collider, and a broad-phase that is only up to date after the last simulation step.

parry is the geometry library underneath rapier, and it answers a smaller question with no bookkeeping at all: do these two shapes, at these two transforms, touch — and where? Nothing is spawned, nothing is stepped, nothing has an Entity. Use it for hypotheticals: can this building be placed here, does this AoE cone cover that point, would the door close if the crate stayed put.

You wantUse
What's in the world near meScene queries — they own the BVH
Two shapes you made up, right nowparry query::*
Contact normal + penetration depthparry query::contact — scene queries won't give you this
Test a shape before spawning itparry — no collider needed
Thousands of pairs per frameScene queries, or build your own index

Where it lives no extra dependency

You already have it. bevy_rapier re-exports rapier, and rapier re-exports parry, so nothing goes in Cargo.toml.

// bevy_rapier3d 0.36 → rapier3d 0.35 → parry3d 0.30
use bevy_rapier2d::parry::{
    query,                                  // the pairwise queries
    shape::{Ball, Cuboid, SharedShape, Shape},
    math::{Pose, Real, Vector},             // parry's own math aliases
    bounding_volume::{Aabb, BoundingVolume},
};

// The long way round works too, and is what the re-export points at:
use bevy_rapier2d::rapier::parry;

Never add parry2d to Cargo.toml yourself. You will get a second copy at a different version, and the two Shape traits are unrelated types. Every error message will be about Shape not implementing Shape.

Poses, points, vectors glam since 0.34

parry used to speak nalgebra. Since the glam migration it speaks the same types Bevy does, which removed nearly all the conversion noise.

// Before (bevy_rapier ≤ 0.33):
//   use parry2d::na::{Point2, Vector2, Isometry2, Unit};
//   let p = Point2::new(1.0, 2.0);
//   let m = Isometry2::translation(1.0, 2.0);
//   collider_fn(p.into(), m.into())      // .into() everywhere

// Now:
use bevy_rapier2d::parry::math::{Pose, Vector};

let v: Vector = Vec2::new(1.0, 2.0);   // Vector IS the glam vector
let p: Vector = point;                 // points are vectors too — no Point type
let n = dir.normalize();               // no Unit<_> wrapper

Pose is parry's transform — translation plus rotation, no scale, which is why scaling a collider rebuilds the shape instead. Shape vs shape the whole point of this section

use bevy_rapier2d::parry::{query, shape::Cuboid, math::{Pose, Vector}};
use bevy_rapier2d::parry::query::ClosestPoints;

/// Would this building fit here? Nothing is spawned to find out.
fn placement_is_legal(ghost: &dyn Shape, at: Pose, obstacles: &[(Pose, Collider)]) -> bool {
    obstacles.iter().all(|(pose, c)| {
        // &*c derefs a bevy_rapier Collider into &dyn Shape.
        !query::intersection_test(&at, ghost, pose, &**c).unwrap_or(false)
    })
}

// Contact: point, direction and depth. This is what scene queries cannot give you.
if let Ok(Some(c)) = query::contact(&pose_a, &shape_a, &pose_b, &shape_b, 0.0) {
    let depth  = -c.dist;         // dist is NEGATIVE while penetrating
    let normal = c.normal1;       // pointing away from shape 1
    let on_a   = c.point1;
    let on_b   = c.point2;
    let separate = normal * depth;
}

// The `prediction` argument is a margin: pass 0.5 and you get contacts for
// shapes up to 0.5 apart, with a positive `dist`. Useful for "almost touching".

// Distance and closest points — proximity UI, AI awareness, snapping.
let gap = query::distance(&pose_a, &shape_a, &pose_b, &shape_b).unwrap_or(f32::MAX);

match query::closest_points(&pose_a, &shape_a, &pose_b, &shape_b, 20.0) {
    Ok(ClosestPoints::Intersecting)        => { /* overlapping */ }
    Ok(ClosestPoints::WithinMargin(p1, p2)) => { draw_line(p1, p2); }
    Ok(ClosestPoints::Disjoint)            => { /* further than 20.0 apart */ }
    Err(_) => { /* unsupported pair */ }
}

Sweeping two moving shapes cast_shapes

The scene-query cast_shape sweeps your shape against a static snapshot of the world. This one lets both sides move, which is what you need for projectile-vs-projectile, or for two things converging in the same frame.

use bevy_rapier2d::parry::query::{self, ShapeCastOptions};

let hit = query::cast_shapes(
    &pose_a, &vel_a, &shape_a,        // velocities are per-unit-of-time,
    &pose_b, &vel_b, &shape_b,        // so t comes back in the same units
    ShapeCastOptions {
        max_time_of_impact: 1.0,
        target_distance: 0.0,
        stop_at_penetration: true,
        compute_impact_geometry_on_penetration: true,
    },
);

match hit {
    Ok(Some(h)) => {
        let t = h.time_of_impact;               // 0.0..=max
        let a_at_impact = pose_a.translation + vel_a * t;
        if let Some(d) = h.details {            // same Option as everywhere else
            let (normal, point) = (d.normal1, d.witness1);
        }
    }
    Ok(None) => { /* they never meet within max_time_of_impact */ }
    Err(_)   => { /* one of them is non-convex — see limits */ }
}

// Rotating motions need the nonlinear version, which takes NonlinearRigidMotion
// (a start pose, a local centre of mass, and linear + angular velocity) instead.

What parry will refuse read this before designing around it

Pair or operationWhat happens
trimesh ↔ trimeshErr(Unsupported) for contact generation. Non-convex vs non-convex has no algorithm
trimesh ↔ heightfield, heightfield ↔ heightfieldSame. Static environment is not meant to collide with static environment
Casting a non-convex shapeUnsupported. A trimesh can be the target of a cast, never the thing being cast
Point inside a trimeshAlways "outside" — a trimesh is a surface with no interior unless built with TriMeshFlags::ORIENTED on a closed mesh
Voxels ↔ mesh / heightfield / voxelsUnsupported, and voxels cannot be shape-cast at all
Round shapes (RoundCuboid, RoundCylinder…)Supported, but fall onto slower generic paths

The fix for all of these is convex decomposition. Collider::convex_decomposition (VHACD) turns a concave mesh into a compound of convex pieces, which collide with everything. It is slow — do it at asset build time, not at spawn.

Building your own index? parry's BVH lives in parry::partitioning and is what rapier's broad phase is made of. The type name has moved around across recent releases, so start from the module docs rather than a snippet. For a few hundred pairs, a linear scan over AABBs from compute_aabb beats the setup cost anyway.

Collision groups

layers, masks, and the two-way rule

The rule both directions must agree

Each collider carries a membership mask (what I am) and a filter mask (what I interact with). Two colliders interact only when:

(A.memberships & B.filter) != 0   &&   (B.memberships & A.filter) != 0

One-sided setups silently do nothing. If bullets filter for enemies but enemies don't filter for bullets, they pass straight through. Both sides, every time.

Declaring layers

const PLAYER:  Group = Group::GROUP_1;
const ENEMY:   Group = Group::GROUP_2;
const BULLET:  Group = Group::GROUP_3;
const TERRAIN: Group = Group::GROUP_4;
// Group::GROUP_1 .. GROUP_32, plus Group::ALL and Group::NONE

// A player bullet: is a BULLET, hits enemies and terrain.
commands.spawn((
    RigidBody::Dynamic,
    Collider::ball(3.0),
    CollisionGroups::new(BULLET, ENEMY | TERRAIN),
    Ccd::enabled(),
));

// The enemy must reciprocate:
CollisionGroups::new(ENEMY, PLAYER | BULLET | TERRAIN)

// Terrain accepts everyone:
CollisionGroups::new(TERRAIN, Group::ALL)

SolverGroups touch but don't push

CollisionGroups decides whether contacts are detected. SolverGroups decides whether detected contacts produce force.

Setting collision groups to allow and solver groups to deny gives you a pair that generates full contact events and manifolds while passing through each other — ghost mode, phasing enemies, one-way triggers that still need normals.

commands.spawn((
    Collider::ball(20.0),
    CollisionGroups::new(GHOST, Group::ALL),   // detected by everything
    SolverGroups::new(GHOST, TERRAIN),         // only terrain can stop it
    ActiveEvents::COLLISION_EVENTS,
));

Physics hooks when masks aren't enough

Bitmasks are static. A hook runs Rust for each candidate pair — the way to build one-way platforms, team-based pass-through, or contact rules that depend on velocity.

use bevy::ecs::system::SystemParam;

#[derive(SystemParam)]
struct OneWayHook<'w, 's> {
    platforms: Query<'w, 's, &'static OneWayPlatform>,
    velocities: Query<'w, 's, &'static Velocity>,
}

impl BevyPhysicsHooks for OneWayHook<'_, '_> {
    fn filter_contact_pair(&self, ctx: PairFilterContext) -> Option<SolverFlags> {
        let (platform, other) = if self.platforms.get(ctx.collider1).is_ok() {
            (ctx.collider1, ctx.collider2)
        } else if self.platforms.get(ctx.collider2).is_ok() {
            (ctx.collider2, ctx.collider1)
        } else {
            return Some(SolverFlags::COMPUTE_IMPULSES);   // not our case
        };

        // Only solid while the other body is moving downward.
        match self.velocities.get(other) {
            Ok(v) if v.linear.y <= 0.0 => Some(SolverFlags::COMPUTE_IMPULSES),
            _ => None,                                     // pass through
        }
    }
}

// Register the hook type on the plugin...
.add_plugins(RapierPhysicsPlugin::<OneWayHook>::pixels_per_meter(100.0))

// ...and opt each collider in:
commands.spawn((
    Collider::cuboid(80.0, 6.0),
    OneWayPlatform,
    ActiveHooks::FILTER_CONTACT_PAIRS,
));

// Other flags: FILTER_INTERSECTION_PAIR, MODIFY_SOLVER_CONTACTS

Character controller

movement that feels authored, not simulated

Setup and read-back

Write a desired translation each frame; rapier slides it along obstacles and writes the corrected result to Transform. Pair it with RigidBody::KinematicPositionBased.

    Collider::capsule_y(20.0, 10.0),

        up: Vec2::Y,

        offset: CharacterLength::Absolute(0.01),

            max_height: CharacterLength::Absolute(12.0),
            min_width:  CharacterLength::Absolute(4.0),
            include_dynamic_bodies: true,
        }),
        max_slope_climb_angle: 45f32.to_radians(),
        min_slope_slide_angle: 30f32.to_radians(),
        snap_to_ground: Some(CharacterLength::Absolute(8.0)),
        apply_impulse_to_dynamic_bodies: true,

    },

fn move_player(
    time: Res<Time>,
    keys: Res<ButtonInput<KeyCode>>,
    mut q: Query<(&mut KinematicCharacterController,
                  Option<&KinematicCharacterControllerOutput>)>,
    mut vy: Local<f32>,
) {
    for (mut controller, output) in &mut q {
        let grounded = output.map(|o| o.grounded).unwrap_or(false);

        if grounded { *vy = 0.0; }
        if grounded && keys.just_pressed(KeyCode::Space) { *vy = 500.0; }
        *vy -= 980.0 * time.delta_secs();

        let mut dx = 0.0;
        if keys.pressed(KeyCode::KeyA) { dx -= 260.0; }
        if keys.pressed(KeyCode::KeyD) { dx += 260.0; }

        controller.translation = Some(Vec2::new(dx, *vy) * time.delta_secs());
    }
}

KinematicCharacterControllerOutput is inserted by the plugin after the first move. Query it as Option or your system silently never runs on frame one.

Notes & limits

  • Collisions with sensors are ignored by the controller. Detect pickups with events or intersection_pairs_with instead.
  • custom_shape lets the controller sweep a different shape than the entity's collider — a slimmer capsule for movement than for hitboxes.
  • Set filter_flags and filter_groups to control what the character sweeps against.
  • Need the raw primitive? RapierContextMut::move_shape does the same sweep-and-slide with no components involved.

Joints

constraints between bodies

Impulse vs multibody

ImpulseJoint — solved with everything else. Fast, allows loops, can stretch under load. The default choice.

MultibodyJoint — reduced-coordinate, cannot drift apart, but forms a strict tree (no closed loops). For robot arms and machinery that must not sag.

Both attach to the child entity and name the parent body.

let anchor = commands.spawn((RigidBody::Fixed, Transform::from_xyz(0.0, 200.0, 0.0))).id();

let joint = RevoluteJointBuilder::new()          // 3D: ::new(Vec3::Z) — the axis
    .local_anchor1(Vec2::new(0.0, 0.0))          // on the parent
    .local_anchor2(Vec2::new(0.0, 60.0))         // on this body
    .limits([-1.2, 1.2])                         // radians
    .motor_velocity(2.0, 0.4);                   // target vel, damping factor

commands.spawn((
    RigidBody::Dynamic,
    Collider::cuboid(8.0, 60.0),
    ImpulseJoint::new(anchor, joint),
));

Scale: pixels_per_meter and length_unit

Rapier's solver is tuned for objects roughly 0.1–10 metres across. A 2D game working in pixels breaks that assumption badly, which shows up as jitter, sinking, and mushy stacks.

pixels_per_meter(100.0) sets rapier's internal length_unit so the solver's thresholds scale with your world. You still author everything in pixels — a Collider::ball(50.0) is a 50 px ball that rapier reasons about as half a metre.

// 2D, working in pixels:
RapierPhysicsPlugin::<NoUserData>::pixels_per_meter(100.0)

// 3D, or 2D authored in metres:
RapierPhysicsPlugin::<NoUserData>::default()

// Remember to scale gravity to match: 9.81 m/s² == 981 px/s².

Ground check three levels of correctness

const HALF_H: f32 = 24.0;
const SKIN:   f32 = 2.0;

// 1. Single ray. Cheap, and wrong on ledges.
fn grounded_ray(rapier: ReadRapierContext, q: Query<(Entity, &Transform), With<Player>>) {
    let Ok(ctx) = rapier.single() else { return };
    for (e, tf) in &q {
        let hit = ctx.cast_ray(
            tf.translation.truncate(), Vec2::NEG_Y, HALF_H + SKIN, true,
            QueryFilter::default().exclude_sensors().exclude_rigid_body(e),
        );
        let grounded = hit.is_some();
    }
}

// 2. Shape cast. Uses the real footprint — the right default.
fn grounded_cast(rapier: ReadRapierContext, q: Query<(Entity, &Transform), With<Player>>) {
    let Ok(ctx) = rapier.single() else { return };
    let feet = Collider::cuboid(10.0, 1.0);
    for (e, tf) in &q {
        let hit = ctx.cast_shape(
            tf.translation.truncate(), 0.0, Vec2::NEG_Y * (HALF_H + SKIN), &*feet,
            ShapeCastOptions { max_time_of_impact: 1.0, stop_at_penetration: false, ..default() },
            QueryFilter::default().exclude_sensors().exclude_rigid_body(e),
        );
        // Reject walls: only count surfaces you could stand on.
        // `details` is None if the shapes already overlapped at t = 0.
        let grounded = hit
            .and_then(|(_, h)| h.details)
            .is_some_and(|d| d.normal1.y > 0.5);
    }
}

// 3. Using the character controller — it already told you.
let grounded = output.grounded;

fn fire(rapier: ReadRapierContext, shooter: Entity, from: Vec2, dir: Vec2) {
    let Ok(ctx) = rapier.single() else { return };

    let filter = QueryFilter::default()
        .exclude_sensors()
        .exclude_rigid_body(shooter)
        .groups(CollisionGroups::new(Group::ALL, ENEMY | TERRAIN));

    if let Some((hit_entity, hit)) = ctx.cast_ray_and_get_normal(
        from, dir.normalize(), 2000.0, true, filter,
    ) {
        spawn_impact(hit.point, hit.normal);
        // Only the first thing along the ray is hit — walls block by construction.
        apply_damage(hit_entity);
    }
}

Explosion damage with falloff

fn explode(rapier: ReadRapierContext, centre: Vec2, radius: f32) {
    let Ok(ctx) = rapier.single() else { return };
    let blast = Collider::ball(radius);
    let mut caught = Vec::new();

    ctx.intersect_shape(centre, 0.0, &*blast,
        QueryFilter::default().exclude_sensors(),
        |e| { caught.push(e); true });

    // Second pass: line of sight, so walls shield.
    for e in caught {
        let Some(pos) = position_of(e) else { continue };
        let to = pos - centre;
        let blocked = ctx.cast_ray(
            centre, to.normalize(), to.length(), true,
            QueryFilter::only_fixed(),
        ).is_some();
        if !blocked {
            let falloff = 1.0 - (to.length() / radius).clamp(0.0, 1.0);
            apply_damage(e, 100.0 * falloff);
        }
    }
}

Teleporting a dynamic body

Writing Transform on a dynamic body works, but the body keeps its old velocity and the move is instantaneous — it can end up inside geometry. Clear velocity, and check the destination first.

fn teleport(
    rapier: ReadRapierContext,
    mut q: Query<(Entity, &mut Transform, &mut Velocity)>,
    dest: Vec2,
) {
    let Ok(ctx) = rapier.single() else { return };
    let shape = Collider::ball(12.0);

    for (e, mut tf, mut v) in &mut q {
        let mut clear = true;
        ctx.intersect_shape(dest, 0.0, &*shape,
            QueryFilter::default().exclude_sensors().exclude_rigid_body(e),
            |_| { clear = false; false });

        if clear {
            tf.translation = dest.extend(tf.translation.z);
            v.linear = Vec2::ZERO;
            v.angular = 0.0;
        }
    }
}

Gotchas

read this before opening an issue

My thing falls through the floor

  • Is it moving fast? Add Ccd::enabled(). A body that travels further than its own thickness in one step can miss entirely.
  • Is the floor a Collider::cuboid with a tiny half-height? Give it real thickness — 1 px floors are tunnels.
  • Are the collision groups reciprocal? Check both directions of the mask test.
  • Did something write Transform directly on the dynamic body this frame? That overrides the solver and can shove it through.
  • Is the floor a trimesh with duplicate vertices? Rebuild with MERGE_DUPLICATE_VERTICES.

My collision events never fire

  • ActiveEvents::COLLISION_EVENTS is missing. It is opt-in, on at least one collider of the pair.
  • Neither body is dynamic — add the relevant ActiveCollisionTypes flag (KINEMATIC_FIXED is the usual one).
  • You're using EventReader on 0.32+. It must be MessageReader.
  • Both colliders are sensors. One side has to be solid.
  • You're checking one slot of the pair. The entity can be in a or b.

Upgrade breakages, newest first

  • 0.36 — simd-stable / simd-nightly gone; SIMD is unconditional. New simd8 feature.
  • 0.34 — Velocity.linvel → linear, angvel → angular. Collider and query APIs take glam types; delete the .into() calls on points and isometries.
  • 0.32 — CollisionEvent, ContactForceEvent, MassModifiedEvent are Messages. EventReader → MessageReader.
  • 0.31 — RapierQueryPipeline stopped being a component. Go through RapierContext or with_query_pipeline.
  • 0.29 — the context split into four components; DefaultReadRapierContext → ReadRapierContext.
  • 0.28 — context and config became components on a context entity; multiple physics worlds became possible.

Smaller traps

  • ExternalForce persists across frames; ExternalImpulse resets itself. Mixing them up gives you a rocket.
  • Bodies read their spawn position from GlobalTransform. A body parented under a moved entity starts where the parent is.
  • Sleeping bodies stop reporting. If a resting object seems inert, that's why — Sleeping::disabled() to opt out.
  • A ray with solid: true that starts inside a shape returns toi = 0.0. That is correct, and it is usually not what you wanted.
  • Cuboids are half-extents; capsules are half-height plus radius. Total height of capsule_y(20.0, 10.0) is 60.
  • Importing both bevy_rapier2d::prelude::* and bevy_rapier3d::prelude::* is a name collision, not a feature.
  • Despawning a body removes its joints and colliders automatically. No manual cleanup needed.

Where to look next

The bevy_rapier2d/examples and bevy_rapier3d/examples folders in the repo are the most reliable documentation in the project — they compile against the exact version you're pinning, which no blog post does. Start with events2, ray_casting2, character_controller3, and joints3.
