[ vectors ]

Four operations run the whole thing

Every contact response is one of these. Learn the difference between rejection and reflection and half the bugs disappear.

Project, reject, reflect

Given a unit surface normal n and a velocity v:

project (the part pushing into the wall)  =  n (v · n)
reject (the part along the wall — this is sliding)  =  v − n (v · n)
reflect (bounce, restitution e)  =  v − (1 + e) n (v · n)

Rejection is reflection with e = 0. Characters almost always want rejection; e > 0 is for grenades and bouncy pads.

use bevy::prelude::*;

let n = hit.normal.normalize();

// slide along the surface
let slide = v.reject_from_normalized(n);

// equivalently, and what you'll see in Quake-lineage code
let slide = v - n * v.dot(n);

// bounce with 40% restitution
let bounce = v - n * (1.0 + 0.4) * v.dot(n);

Vec3::normalize returns NaN on a zero vector. Use normalize_or_zero(), or Dir3::new(v) which hands you a Result.

Dot products are your entire query language

With unit vectors, a.dot(b) is cos θ. Nearly every question a controller asks reduces to one comparison.

The collide-and-slide loop

Sweep the shape, stop short by a skin, project the leftover motion onto the contact plane, repeat. Bounded iterations, no springs, no penetration.

The reference implementation

One frame of motion becomes up to MAX_BOUNCES sweeps. Each recursion spends part of the displacement and redirects the rest.

use avian3d::prelude::*;
use bevy::prelude::*;

const SKIN: f32 = 0.015;        // stay this far off every surface
const MAX_BOUNCES: u32 = 5;     // 4-5 is plenty; more just burns queries

/// Returns the displacement actually achievable this frame.
fn collide_and_slide(
    q: &SpatialQuery,
    shape: &Collider,
    pos: Vec3,
    vel: Vec3,               // displacement, i.e. velocity * dt
    depth: u32,
    filter: &SpatialQueryFilter,
) -> Vec3 {
    if depth >= MAX_BOUNCES {
        return Vec3::ZERO;   // give up rather than tunnel
    }
    let Ok(dir) = Dir3::new(vel) else { return Vec3::ZERO };
    let len = vel.length();

    let Some(hit) = q.cast_shape(
        shape, pos, Quat::IDENTITY, dir,
        &ShapeCastConfig::from_max_distance(len + SKIN),
        filter,
    ) else {
        return vel;          // free flight, we're done
    };

    // 1. advance to just short of the surface
    let travel = dir * (hit.distance - SKIN).max(0.0);

    // 2. whatever we didn't spend gets redirected, not deleted
    let leftover = vel - travel;

    // 3. strip the component driving into the plane
    let n = hit.normal1;
    let slid = leftover.reject_from_normalized(n);

    travel + collide_and_slide(q, shape, pos + travel, slid, depth + 1, filter)
}

Why each line is there

  • Skin width. Floating point contact at exactly distance 0 re-hits next frame at distance 0 and the sweep returns nothing useful. Park 0.01–0.02 world units off every surface, forever.
  • .max(0.0). If hit.distance < SKIN you already started inside geometry. Clamping stops you from travelling backwards; the real fix is a depenetration pass before the move.
  • Reject, don't rescale. Cutting leftover to zero is sweep-and-stop: you slam to a halt on every glancing wall. Projecting keeps tangential speed and gives the sliding.
  • Bounded recursion. Three near-parallel planes can ping-pong forever. Returning ZERO at the cap loses a sliver of movement in one frame and never hangs.

Corners, creases, and wedges

Projecting onto plane B can push you straight back into plane A. Naive sliding vibrates in every inside corner. Keep the planes you've hit this frame and re-check.

// after computing `slid` against the new plane n
for prev in &planes {
    if slid.dot(*prev) < 0.0 {
        // moving back into an earlier plane:
        // ride the crease where they meet
        let crease = prev.cross(n).normalize_or_zero();
        slid = crease * slid.dot(crease);
        break;
    }
}
planes.push(n);

// three constraining planes = a pocket. Stop.
if planes.len() >= 3 { slid = Vec3::ZERO; }

In 2D a crease collapses to a point, so the character simply stops — that's the wedge state in the diagram above.

Overbounce, and splitting the move

Quake's ClipVelocity

fn clip_velocity(v: Vec3, n: Vec3, overbounce: f32) -> Vec3 {
    let backoff = v.dot(n) * overbounce;
    v - n * backoff
}
// overbounce = 1.001 pushes a hair *away* from
// the plane so rounding can't re-penetrate it.

Two passes beat one

Run the horizontal move and the vertical move as separate solves:

  • Horizontal pass with gravity stripped out, so running up a ramp doesn't convert forward speed into launch speed at the crest.
  • Vertical pass for gravity and jumping, so landing on a slope doesn't shove you sideways.

When grounded, also flatten walkable normals against up before projecting — otherwise walking into a gentle slope quietly steals or adds vertical speed each frame.

[ shapes ]

What you sweep decides how you snag

The collider is a movement design decision, not a physics detail. Sharp corners catch on seams; round bottoms slide off ledges.

Picking one

ShapeUse it when
CapsuleDefault for humanoids. A segment plus a radius, so the sweep is cheap and exact, and nothing can catch on a corner. Cost: the rounded foot slides off ledges and lets you creep up slightly steeper slopes than the limit near edges.
CylinderPlatformers and anything where standing on a ledge edge must feel solid. Cost: the rim snags on floor seams, so you need step offset and a fatter skin.
SphereBalls, drones, tiny critters. Cost: no consistent up, no clean grounding.
Box / AABBVoxel and grid worlds where axes are guaranteed and you can sweep analytically. Cost: every seam is a wall.
CompoundCapsule for the body plus a separate short cast for feet. Best of both, two queries.

Never rotate the character collider with the camera. Yaw the mesh, keep the collider upright — a rotating capsule changes what fits through a door depending on where you're looking.

[ ground ]

Grounding is a state machine, not a boolean

Getting on the floor right fixes more feel problems than any amount of acceleration tuning.

Detect, classify, snap

#[derive(Component, Default)]
struct Grounded {
    on_ground: bool,
    normal: Vec3,
    since: f32,       // seconds airborne, for coyote time
}

const MAX_SLOPE: f32 = 50.0_f32.to_radians();
const PROBE: f32 = 0.35;   // how far below the feet to look

// cast the same shape straight down, shrunk slightly
// so it can't catch the wall you're pressed against
let probe = Collider::capsule(radius * 0.95, cyl_height);
let hit = q.cast_shape(
    &probe, pos, Quat::IDENTITY, Dir3::NEG_Y,
    &ShapeCastConfig::from_max_distance(PROBE),
    &filter,
);

let walkable = hit
    .filter(|h| h.normal1.dot(Vec3::Y) >= MAX_SLOPE.cos());

Ground snapping

After a horizontal move, if you were grounded, aren't jumping, and the probe finds walkable ground within the snap distance — teleport onto it.

if was_grounded && vel.y <= 0.0 && !jumped {
    if let Some(h) = walkable {
        transform.translation.y -= h.distance - SKIN;
        vel.y = 0.0;
    }
}

Without this you launch off every ramp crest and bounce down every staircase. With it, ramps feel welded to your feet.

Steps: up, forward, down

Run the three casts against a copy of the position. Commit only if all three succeed and the final surface passes the slope test — otherwise you'll teleport onto steep rubble and up ladders.

Slopes you can't climb

A too-steep face is a wall, not a floor. Treat it as one, then decide whether it also sheds you.

if n.dot(Vec3::Y) < MAX_SLOPE.cos() {
    // 1. it blocks like a wall
    vel = vel.reject_from_normalized(n);
    // 2. optionally, slide down it
    let down_slope = Vec3::NEG_Y
        .reject_from_normalized(n)
        .normalize_or_zero();
    vel += down_slope * SLIDE_ACCEL * dt;
    grounded.on_ground = false;   // no jumping off it
}

Add a small hysteresis (a degree or two) between the "start sliding" and "stop sliding" angles or you'll chatter on the boundary.

Moving platforms

Never parent the character to the platform — you inherit its rotation and scale and everything shears. Carry the delta instead.

// each frame, before your own move
if let Some(p) = grounded.platform {
    let now = platform_xf.compute_matrix();
    let local = grounded.last_inv * pos.extend(1.0);
    let carried = (now * local).xyz() - pos;
    pos += carried;                 // translation + spin
    grounded.last_inv = now.inverse();
}

Store the platform's inverse transform at the moment of contact and re-apply it. That gets you rotating platforms for free, and jumping off inherits the platform's velocity if you add carried / dt to your own.

[ feel ]

Smoothness is scheduling, not filtering

Most "floaty" controllers are frame-rate-dependent lerps. Most "sticky" ones smooth their input. Fix the maths and the feel follows.

Accelerate and rub: the Quake model

Thirty years old and still the best-feeling ground movement anyone has shipped. Friction first, then acceleration.

fn apply_friction(v: Vec3, friction: f32, stop_speed: f32, dt: f32) -> Vec3 {
    let speed = v.length();
    if speed < 1e-4 { return Vec3::ZERO; }
    // stop_speed gives a constant drag floor so you
    // actually come to rest instead of easing forever
    let drop = speed.max(stop_speed) * friction * dt;
    v * ((speed - drop).max(0.0) / speed)
}

fn accelerate(v: Vec3, wish_dir: Vec3, wish_speed: f32, accel: f32, dt: f32) -> Vec3 {
    // how much speed we're still missing *in that direction*
    let add = wish_speed - v.dot(wish_dir);
    if add <= 0.0 { return v; }
    v + wish_dir * (accel * wish_speed * dt).min(add)
}

The projection v.dot(wish_dir) is the whole trick: it only ever tops you up along the direction you're asking for, so turning is instant but the speed cap is never violated along that axis.

Call accelerate in the air with a much smaller wish_speed (Quake uses ~30 vs ~320) and you get air strafing and bunny hopping as an emergent bonus.

Framerate-independent smoothing

a.lerp(b, 0.1) per frame is a different curve at 60 fps and 144 fps. The fix is exponential decay.

t = 1 − e^(−λ · dt)
// λ ≈ 8 is gentle, ≈ 20 is snappy.
// 1/λ is roughly the time to cover 63% of the gap.
let t = 1.0 - (-lambda * dt).exp();
current = current.lerp(target, t);

// Bevy ships this as StableInterpolate:
use bevy::math::StableInterpolate;
current.smooth_nudge(&target, lambda, dt);

Half-life form, if you prefer thinking in seconds

let t = 1.0 - 2f32.powf(-dt / half_life);

Use this for the camera, the mesh's visual yaw, FOV kick, and crouch height. Do not use it on raw look input — smoothing the mouse just adds latency that players read as input lag.

Jump maths you can design against

Nobody can tune "gravity = −24". Everyone can tune "1.2 m high, 0.35 s to the top".

g = 2h / tapex²   v₀ = 2h / tapex
#[derive(Component)]
struct JumpTuning { height: f32, t_apex: f32 }

impl JumpTuning {
    fn gravity(&self)    -> f32 { 2.0 * self.height / (self.t_apex * self.t_apex) }
    fn launch_speed(&self) -> f32 { 2.0 * self.height / self.t_apex }
}

If you only know the height, v₀ = (2 · g · h).sqrt().

Asymmetric gravity

let g = if vel.y > 0.0 && jump_held { rise_g }
        else if vel.y > 0.0          { rise_g * 2.2 }  // released early
        else                         { rise_g * 1.6 }; // falling

Heavier falls read as "responsive", not "wrong". Clamping |vel.y| near the apex for ~0.1 s buys you the hang time platformers live on.

Forgiveness buffers

Both of these hide input timing error from the player. Ship both, always.

// coyote time: jump shortly *after* walking off
if grounded.on_ground { coyote = COYOTE; }
else { coyote = (coyote - dt).max(0.0); }

// jump buffer: jump shortly *before* landing
if input.just_pressed(KeyCode::Space) { buffer = BUFFER; }
else { buffer = (buffer - dt).max(0.0); }

if buffer > 0.0 && coyote > 0.0 {
    vel.y = tuning.launch_speed();
    buffer = 0.0;
    coyote = 0.0;   // consume both, or you double-jump
}

[ plumbing ]

Wiring it into Bevy

Fixed timestep for the simulation, interpolation for the render, and one clear owner of the transform.

Schedule layout

app
  // input accumulates every render frame so no press is lost
  .add_systems(Update, (read_input, buffer_jump).chain())
  // simulation runs at a fixed rate
  .add_systems(FixedUpdate, (
      apply_friction,
      apply_input_accel,
      apply_gravity,
      resolve_move,      // collide_and_slide
      probe_ground,
  ).chain().in_set(MovementSet))
  // render transform catches up smoothly
  .add_systems(RunFixedMainLoop, interpolate_visuals
      .in_set(RunFixedMainLoopSystem::AfterFixedMainLoop))
  .insert_resource(Time::::from_hz(60.0));

Inside FixedUpdate, Time::delta_secs() already resolves to the fixed delta — you don't need Time<Fixed> explicitly.

Render interpolation

let alpha = fixed_time.overstep_fraction();
visual.translation = prev.lerp(current, alpha);

Keep the physics position on your own component and let the interpolation own Transform, or the two will fight and you'll see jitter that looks exactly like a collision bug.

Depenetration, for when you end up inside something

Spawning, teleporting, a platform closing on you, a designer moving a wall — you will start a frame overlapping. Push out before you try to move, and clamp how fast.

const MAX_PUSH_SPEED: f32 = 3.0;   // m/s, so a bad overlap doesn't fling you

for other in spatial.shape_intersections(&collider, pos, rot, &filter) {
    // ask the backend for the minimum translation vector
    let Some((dir, depth)) = mtv(&collider, pos, other) else { continue };
    let push = (depth - SKIN).max(0.0).min(MAX_PUSH_SPEED * dt);
    pos += dir * push;
}
  • Resolve one contact per frame at most if you can. Summing MTVs from two opposing walls cancels them out and you stay stuck.
  • Never depenetrate against a moving platform by its full depth — clamp it, or a lift closing on you launches you through the ceiling.
  • Depenetration is not movement. Don't feed the push back into velocity; the character didn't earn that speed.
