Project structure

res://

Godot doesn't enforce a layout, so pick one on day one and never reorganise mid-project — moving files rewrites every path reference and dirties your whole diff.

Feature folders — the layout that scales

res://
├── addons/              # plugins — never edit by hand
├── assets/              # raw imports, no scenes here
│   ├── art/  audio/  fonts/
├── scenes/
│   ├── player/          # player.tscn + player.gd + player_states/
│   ├── enemies/
│   │   ├── enemy.gd     # shared base class
│   │   └── slime/       # slime.tscn + slime.gd + slime.png
│   ├── levels/
│   ├── ui/              # hud.tscn, pause_menu.tscn, main_menu.tscn
│   └── components/      # health.tscn, hitbox.tscn, hurtbox.tscn
├── scripts/
│   ├── globals/         # autoloads: game.gd, events.gd, audio.gd
│   └── utils/           # pure static helpers, no scene attached
├── resources/           # .tres data: items, stats, themes, curves
├── shaders/
└── project.godot

Rule of thumb: a scene, its script and its private assets live in one folder. If you can't delete a folder without breaking something outside it, the boundary is wrong. scripts/ is only for code with no scene of its own.

The two filesystems

res://Your project. Read-only in an exported build — it's inside the .pck.
user://Writable. Saves, settings, logs. Per-OS app data dir.
# See where user:// actually points
print(OS.get_user_data_dir())

# Absolute paths for a native file dialog
var abs := ProjectSettings.globalize_path("user://save.dat")

Trap: writing to res:// works in the editor and silently fails after export. Every save path starts with user://.

Version control

Commit .tscn, .tres and .import files — they're text and they merge. Never commit the import cache.

# .gitignore

export_presets.cfg   # holds signing keys

Set Editor → Version Control or just use git externally. Binary art files benefit from Git LFS.

Naming & script order

style guide

The official GDScript style guide, condensed. Following it means every tutorial, plugin and Stack Overflow answer reads like your own code.

Naming

player_ship.gdfiles & folders — snake_case
PlayerShipclasses & nodes — PascalCase
max_speedvariables & functions
MAX_SPEEDconstants
_recalculate()private — leading underscore
health_depletedsignals — past tense
State.IDLEenums — PascalCase name, CONSTANT members

Watch: a file named Player.gd and one named player.gd are the same file on Windows and different files on Linux. Stay lowercase.

Declaration order inside a script

@tool
class_name Enemy
extends CharacterBody2D
## Doc comment: shows in the editor help.

signal died(by: Node)

enum State { IDLE, CHASE, DEAD }

const GRAVITY := 980.0

static var alive_count := 0

@export var max_health := 30

GDScript syntax

the whole language, roughly

Python-shaped, but statically typed when you want it to be. Type your variables: you get autocomplete, compile-time errors and a real speed-up.

Variables & typing

var loose = 5              # dynamic — avoid
var typed: int = 5        # explicit
var inferred := 5         # := infers int. Preferred.

const MAX := 100          # compile-time constant
static var counter := 0  # shared across instances

var nums: Array[int] = [1, 2, 3]   # typed array
var tally: Dictionary = {"hp": 10}
var pos := Vector2(4, 9)
var maybe: Node = null

# Setter / getter
var health := 100:
    set(value):
        health = clampi(value, 0, 100)
        health_changed.emit(health)
    get:
        return health

Control flow

    var item = queue.pop_front()
    if item == null: continue

match state:
    State.IDLE: _idle()
    State.CHASE, State.FLEE: _move()
    var other: push_error("bad: %s" % other)

    [0, var b]: print("on y axis at %d" % b)
    [var a, ..]: print("starts with %d" % a)

Trap: exported values are baked into the .tscn when you set them in the inspector. Changing the default in code will not update instances that already have an override — clear the override with the revert arrow.

@tool — run script in the editor

@tool
extends Node2D

@export var radius := 64.0:
    set(v):
        radius = v
        queue_redraw()     # live preview

func _draw() -> void:
    draw_circle(Vector2.ZERO, radius, Color.CYAN)

func _process(_d) -> void:
    if Engine.is_editor_hint(): return
    # game-only logic here

Careful: a crash in a @tool script crashes the editor. Guard everything with Engine.is_editor_hint().

Nodes & scenes

get_node / instantiate

A scene is a tree of nodes saved to disk. Instancing one gives you a node you can add anywhere. That's the entire architecture.

Getting references

@onready var sprite: Sprite2D = $Sprite2D
@onready var bar: ProgressBar = $UI/HBox/HealthBar
@onready var hp: Label = %HealthLabel   # scene-unique name

get_node("Sprite2D")          # same as $Sprite2D
get_node_or_null("Maybe")    # null instead of error
get_parent()
get_child(0)  /  get_children()
get_tree().current_scene
get_tree().root                 # the Window
find_child("Coin*", true, false)  # recursive, slow

Use % over deep paths. Right-click a node → Access as Unique Name. Then %HealthLabel keeps working after you reparent it. $UI/HBox/HealthBar breaks.

Instancing & freeing

const BULLET := preload("res://scenes/bullet/bullet.tscn")

func shoot() -> void:
    var b := BULLET.instantiate() as Bullet
    # Add to the world, NOT to self — otherwise the
    # bullet inherits the player's rotation and movement.
    get_tree().current_scene.add_child(b)
    b.global_position = %Muzzle.global_position
    b.direction = Vector2.RIGHT.rotated(rotation)

queue_free()          # deletes at end of frame — always use this
free()                # immediate; crashes if still in use
node.get_parent().remove_child(node)  # detach, keep alive
if is_instance_valid(node): node.do_thing()

preload loads at parse time (constant path only). load loads at runtime and accepts a variable.

Groups — the loose-coupling escape hatch

add_to_group("enemies")
remove_from_group("enemies")
if is_in_group("enemies"): pass

var all := get_tree().get_nodes_in_group("enemies")
get_tree().call_group("enemies", "stun", 2.0)
get_tree().get_node_count_in_group("enemies")

Also settable in the editor's Node → Groups tab. Great for "pause everything", "save all", "reset level".

Ordering & visibility

z_index = 10                # 2D draw order within a parent
y_sort_enabled = true      # top-down depth sorting
move_child(node, 0)         # reorder siblings

visible = false            # hides children too
set_process(false)         # stop _process only

Pause menus: set the menu's process_mode to Always (or When Paused), then set get_tree().paused = true. Otherwise your menu freezes with the game.

Lifecycle callbacks

virtual methods

Order of events, and what belongs where

CallbackWhenUse for
_init()Object created, before entering treePure data setup. No $Node access.
_enter_tree()Added to tree, parents ready firstRegistering with managers
_ready()Node and all children are in tree. Children fire first.Node references, signal connections, initial state
_process(delta)Every rendered frame, variable rateVisuals, UI, input polling, camera
_physics_process(delta)Fixed 60 Hz by defaultMovement, collisions, anything with a body
_input(event)Every event, before UIGlobal hotkeys — rarely what you want
_unhandled_input(event)After UI consumed its eventsGameplay input. Prefer this.
_exit_tree()Removed from treeDeregistering, cleanup
_notification(what)Engine messagesWindow close, predelete, app pause
func _notification(what: int) -> void:
    match what:
        NOTIFICATION_WM_CLOSE_REQUEST: SaveManager.save(); get_tree().quit()
        NOTIFICATION_APPLICATION_FOCUS_OUT: get_tree().paused = true
        NOTIFICATION_PREDELETE: print("about to be freed")

The classic bug: _ready() runs children-first, bottom-up. A parent can safely touch its children in _ready; a child cannot assume its parent is ready. Defer with call_deferred() or await owner.ready.

Signals

call down, signal up

The architectural rule that keeps Godot projects from collapsing: a parent may call methods on its children directly; a child must never reach up. It emits, and the parent listens.

Declare, emit, connect

# --- health.gd (the child) ---
signal health_changed(current: int, maximum: int)
signal died

func take_damage(n: int) -> void:
    current = maxi(current - n, 0)
    health_changed.emit(current, maximum)
    if current == 0:
        died.emit()

# --- player.gd (the parent) ---
func _ready() -> void:
    %Health.health_changed.connect(_on_health_changed)
    %Health.died.connect(_on_died, CONNECT_ONE_SHOT)

func _on_health_changed(cur: int, maxv: int) -> void:
    %Bar.value = float(cur) / maxv

Flags: CONNECT_ONE_SHOT, CONNECT_DEFERRED (fires at idle — safe for freeing nodes), CONNECT_PERSIST.

Managing connections

sig.disconnect(_on_thing)
if sig.is_connected(_on_thing): pass

# Bind extra args (appended after signal args)
for i in buttons.size():
    buttons[i].pressed.connect(_on_slot.bind(i))

func _on_slot(index: int) -> void:
    print("clicked slot %d" % index)

# Lambdas work too
timer.timeout.connect(func(): queue_free())

Trap: lambdas capturing self keep connections alive in ways that are hard to disconnect. Use a named method when you'll ever need to unhook it.

await — signals as coroutines

func intro() -> void:
    %Anim.play("door_open")
    await %Anim.animation_finished

    await get_tree().create_timer(1.5).timeout
    print("1.5s later")

    await get_tree().process_frame   # wait one frame

    var choice = await %Dialog.option_picked  # capture args

# await another function that itself awaits
await intro()

Trap: after an await, the node may have been freed. Check if not is_instance_valid(self): return before touching anything.

Input

Project → Input Map

Never hard-code a key. Define actions in the Input Map, and rebinding, gamepads and accessibility all come free.

Polling — for continuous state

func _physics_process(delta: float) -> void:
    # -1..1 on one axis
    var x := Input.get_axis("move_left", "move_right")

    # normalised 2D vector, deadzone handled
    var dir := Input.get_vector(
        "move_left", "move_right",
        "move_up", "move_down")

    if Input.is_action_just_pressed("jump"): jump()
    if Input.is_action_pressed("fire"): shoot()
    if Input.is_action_just_released("charge"): release()

    var strength := Input.get_action_strength("accelerate")

Events — for discrete moments

func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("pause"):
        toggle_pause()
        get_viewport().set_input_as_handled()

    if event is InputEventMouseButton and event.pressed:
        if event.button_index == MOUSE_BUTTON_LEFT:
            click_at(event.position)

    if event is InputEventMouseMotion:
        aim(event.relative)

    if event is InputEventKey and event.keycode == KEY_ESCAPE:
        pass

# Mouse capture for FPS games
Input.mouse_mode = Input.MOUSE_MODE_CAPTURED
Input.mouse_mode = Input.MOUSE_MODE_VISIBLE

_input sees everything first; _unhandled_input only gets what the UI didn't consume. Gameplay belongs in the latter so clicking a button doesn't also fire your gun.

Rebinding at runtime

func rebind(action: String, event: InputEvent) -> void:
    InputMap.action_erase_events(action)
    InputMap.action_add_event(action, event)

# Human-readable key name for the options menu
var events := InputMap.action_get_events("jump")
%Label.text = events[0].as_text()

# Actions can also be created entirely in code
InputMap.add_action("dash", 0.2)  # deadzone

2D movement

CharacterBody2D

Platformer — with coyote time & jump buffer

extends CharacterBody2D

@export var speed := 300.0
@export var jump_velocity := -420.0
@export var accel := 1800.0
@export var friction := 2200.0
@export var coyote_time := 0.12
@export var jump_buffer := 0.12

var _coyote := 0.0
var _buffer := 0.0

func _physics_process(delta: float) -> void:
    # Gravity from Project Settings
    if not is_on_floor():
        velocity += get_gravity() * delta
        _coyote -= delta
    else:
        _coyote = coyote_time

    if Input.is_action_just_pressed("jump"):
        _buffer = jump_buffer
    _buffer -= delta

    if _buffer > 0.0 and _coyote > 0.0:
        velocity.y = jump_velocity
        _buffer = 0.0
        _coyote = 0.0

    # Variable jump height: cut it short on release
    if Input.is_action_just_released("jump") and velocity.y < 0.0:
        velocity.y *= 0.45

    var dir := Input.get_axis("move_left", "move_right")
    if dir != 0.0:
        velocity.x = move_toward(velocity.x, dir * speed, accel * delta)
        %Sprite.flip_h = dir < 0.0
    else:
        velocity.x = move_toward(velocity.x, 0.0, friction * delta)

    move_and_slide()

Choosing a body type

CharacterBody2DYou control movement in code. Players, enemies, most things.
RigidBody2DPhysics owns it. Debris, crates, ragdolls. Push via apply_impulse(), never by setting position.
StaticBody2DDoesn't move. Walls, floors.
AnimatableBody2DMoved by code/animation, pushes rigid bodies correctly. Platforms, doors.
Area2DDetection only, no collision response. Pickups, hurtboxes, triggers.

Trap: setting position directly on a RigidBody fights the physics engine. Use apply_central_impulse(), or switch to freeze_mode / PhysicsDirectBodyState.

3D movement & camera

CharacterBody3D

First-person controller

extends CharacterBody3D

@export var speed := 5.0
@export var jump_velocity := 4.5
@export var mouse_sens := 0.003

@onready var cam: Camera3D = %Camera3D

func _ready() -> void:
    Input.mouse_mode = Input.MOUSE_MODE_CAPTURED

func _unhandled_input(event: InputEvent) -> void:
    if event is InputEventMouseMotion:
        rotate_y(-event.relative.x * mouse_sens)
        cam.rotate_x(-event.relative.y * mouse_sens)
        cam.rotation.x = clampf(cam.rotation.x,
            deg_to_rad(-89), deg_to_rad(89))

func _physics_process(delta: float) -> void:
    if not is_on_floor():
        velocity += get_gravity() * delta
    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity

    var input := Input.get_vector(
        "move_left", "move_right",
        "move_forward", "move_back")
    # Convert to world space relative to facing
    var dir := (transform.basis * Vector3(input.x, 0, input.y)).normalized()

    velocity.x = move_toward(velocity.x, dir.x * speed, speed * 8 * delta)
    velocity.z = move_toward(velocity.z, dir.z * speed, speed * 8 * delta)
    move_and_slide()

Physics, areas & raycasts

layers & masks

Layers vs masks — the one thing to internalise

Layer = "what I am". Mask = "what I look for". They're independent, and detection is one-directional unless both sides opt in.

LayerNameTypical mask
1World—
2Player1, 4, 6
3Enemy1, 5
4Enemy hitbox—
5Player hitbox—
6Pickups—
# Name your layers: Project Settings → Layer Names → 2D Physics
collision_layer = 0b0010          # I am on layer 2
collision_mask  = 0b0101          # I detect layers 1 and 3

set_collision_layer_value(2, true)   # readable version
set_collision_mask_value(3, false)

The #1 "why isn't my collision working" cause: the Area's mask doesn't include the body's layer. Turn on Debug → Visible Collision Shapes and check both sides.

Area2D — pickups & hurtboxes

extends Area2D

func _ready() -> void:
    body_entered.connect(_on_body_entered)
    area_entered.connect(_on_area_entered)

func _on_body_entered(body: Node2D) -> void:
    if body is Player:
        body.collect(1)
        set_deferred("monitoring", false)  # stop double pickup
        queue_free()

# Manual query instead of signals
for b in get_overlapping_bodies(): print(b.name)
for a in get_overlapping_areas(): print(a.name)

Trap: you can't change collision state during a physics callback. Use set_deferred() or call_deferred() or you'll get a "flushing queries" error.

Raycasts

# Node-based: RayCast3D / RayCast2D child
@onready var ray: RayCast2D = %RayCast2D

func _physics_process(_d) -> void:
    if ray.is_colliding():
        var hit := ray.get_collider()
        var point := ray.get_collision_point()
        var normal := ray.get_collision_normal()

ray.target_position = Vector2(0, 100)  # LOCAL space!
ray.force_raycast_update()             # query right now
ray.add_exception(self)

# Code-based, one-shot
func shoot_ray(from: Vector2, to: Vector2) -> Dictionary:
    var space := get_world_2d().direct_space_state
    var q := PhysicsRayQueryParameters2D.create(from, to)
    q.exclude = [get_rid()]
    q.collision_mask = 0b0001
    return space.intersect_ray(q)   # {} if nothing hit

Screen shake & juice

extends Camera2D

var _trauma := 0.0
@export var decay := 1.8
@export var max_offset := Vector2(14, 10)

func shake(amount: float) -> void:
    _trauma = minf(_trauma + amount, 1.0)

func _process(delta: float) -> void:
    if _trauma <= 0.0: return
    _trauma = maxf(_trauma - decay * delta, 0.0)
    var s := _trauma * _trauma      # squared feels better
    offset = Vector2(
        max_offset.x * s * randf_range(-1, 1),
        max_offset.y * s * randf_range(-1, 1))

# Hit-stop: freeze briefly on impact

    Engine.time_scale = 0.02
    await get_tree().create_timer(duration, true, false, true).timeout
    Engine.time_scale = 1.0

Autoloads & the event bus

Project → Autoload

Autoloads are singletons added to the root before your scene loads, reachable by name from anywhere. Powerful, and the easiest thing in Godot to over-use — three or four is a healthy project.

A global event bus

# res://scripts/globals/events.gd — autoload as "Events"
extends Node

signal player_died
signal score_changed(total: int)
signal enemy_killed(enemy: Node, points: int)
signal dialogue_started(id: StringName)

# --- anywhere ---
Events.enemy_killed.emit(self, 150)

# --- hud.gd ---
func _ready() -> void:
    Events.score_changed.connect(_on_score_changed)

This decouples systems that shouldn't know each other exist — the HUD never needs a reference to the player.

A game state singleton

# res://scripts/globals/game.gd — autoload as "Game"
extends Node

var score := 0:
    set(v):
        score = v
        Events.score_changed.emit(v)

var current_level := 1
var settings := {"master": 1.0, "fullscreen": false}

func reset_run() -> void:
    score = 0
    current_level = 1

Discipline: autoloads should hold state and broadcast, not reach into scenes. The moment one starts doing get_node("/root/Main/Player"), it's become hidden coupling.

What belongs in an autoload

  • Yes: event bus, save/load, audio manager, scene transitions, run-wide state, settings
  • No: the player, the level, anything with a visual presence, anything you might want two of

Alternatives before you add a fifth autoload: a static variable on a class_name'd script, a plain Resource passed by export, or a group.

Custom resources

Resource / .tres

The most under-used feature in Godot. A custom Resource is a data file you can create in the FileSystem dock, edit in the inspector and drag into any export slot — data-driven design with no parser to write.

Define it, author it, use it

# res://resources/item_data.gd
class_name ItemData
extends Resource

@export var display_name: String = "Unnamed"
@export var icon: Texture2D
@export_multiline var description: String
@export var value := 10
@export var stackable := true
@export var on_use: PackedScene

func describe() -> String:
    return "%s (%dg)" % [display_name, value]

# Then: FileSystem → right-click → New Resource → ItemData
# Save as res://resources/items/health_potion.tres, fill it in.

# --- consume it ---
extends Area2D
@export var data: ItemData          # drag the .tres in

func _ready() -> void:
    %Sprite.texture = data.icon
    %Label.text = data.describe()

# Or load a whole folder of them
var potion: ItemData = load("res://resources/items/health_potion.tres")

Same pattern for enemy stat blocks, weapon definitions, dialogue trees, level configs, ability data. One designer-editable file per thing, versioned as text.

Trap: resources are shared by default. Two enemies exporting the same EnemyStats.tres mutate each other's health. Either keep resources immutable (read-only stats, state lives on the node) or call data = data.duplicate() in _ready. Ticking Local to Scene on the resource does this automatically.

Saving & loading

user://

JSON — readable, portable, safe

const PATH := "user://save_01.json"

func save_game() -> void:
    var data := {
        "version": 2,
        "level": Game.current_level,
        "score": Game.score,
        "pos": {"x": player.position.x, "y": player.position.y},
        "inventory": Game.inventory_ids,
    }
    var f := FileAccess.open(PATH, FileAccess.WRITE)
    if f == null:
        push_error(FileAccess.get_open_error()); return
    f.store_string(JSON.stringify(data, "  "))
    f.close()

func load_game() -> bool:
    if not FileAccess.file_exists(PATH): return false
    var f := FileAccess.open(PATH, FileAccess.READ)
    var parsed = JSON.parse_string(f.get_as_text())
    if typeof(parsed) != TYPE_DICTIONARY: return false
    Game.score = int(parsed.get("score", 0))
    return true

Always store a version number. Your save format will change, and old saves shouldn't crash the game.

Performance

profiler

Measure first

  • Debugger → Profiler for script cost; Visual Profiler for GPU cost. Guessing wastes days.
  • Monitors tab shows draw calls, objects, orphan nodes. Orphan count climbing = you're leaking nodes.
  • Run with --verbose to see what's loading.
print(Performance.get_monitor(Performance.TIME_FPS))
print(Performance.get_monitor(Performance.OBJECT_NODE_COUNT))
print(Performance.get_monitor(Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME))

The reliable wins

  • Type everything. Static typing is measurably faster than dynamic.
  • Don't allocate per frame. No new(), no instantiate(), no load() in _process.
  • Cache node lookups in @onready vars, never get_node() in a loop.
  • Turn off processing on idle nodes: set_process(false).
  • Signals over polling. Don't check a condition every frame if something can tell you.
  • Pool bullets and particles instead of instantiating and freeing.
  • VisibleOnScreenEnabler2D auto-disables off-screen nodes.
  • MultiMeshInstance for thousands of identical objects.
  • Move heavy work to WorkerThreadPool or spread it across frames.
# Simple object pool
var _pool: Array[Node2D] = []

func spawn() -> Node2D:
    var b: Node2D
    if _pool.is_empty():
        b = BULLET.instantiate()
        add_child(b)
    else:
        b = _pool.pop_back()
    b.visible = true
    b.set_physics_process(true)
    return b

func recycle(b: Node2D) -> void:
    b.visible = false
    b.set_physics_process(false)
    _pool.append(b)

Gotchas

hard-won

Timing & frames

  • Multiply by delta for anything per-second. Forgetting it makes your game run at monitor speed.
  • Movement goes in _physics_process, visuals in _process. Mixing them causes jitter.
  • Turn on physics interpolation (Project Settings) if 2D movement still looks choppy.
  • await yields — code after it runs later, possibly after the node is freed.
  • queue_free() defers to end of frame. The node is still valid on the next line but is_queued_for_deletion() is true.

References & values

  • Arrays, Dictionaries and Objects are passed by reference. var b = a then editing b edits a. Use a.duplicate(true) for a deep copy.
  • Vector2/3, Color, Rect2 are values. node.position.x = 5 works, but var p = node.position; p.x = 5 changes nothing.
  • Resources are shared across every scene instance unless Local to Scene is ticked.
  • Never compare floats with ==. Use is_equal_approx().

Tree & transform

  • position is relative to the parent; global_position is absolute. Setting the wrong one is the most common spawn bug.
  • Set global_position only after add_child() — before that the node has no global frame of reference.
  • A rotated or scaled parent transforms its children. Add projectiles to the level, not to the gun.
  • $Path/To/Node breaks the moment you reorganise. Use %UniqueName.
  • Don't rename nodes casually — every $ path and animation track that references them breaks silently.

Physics & errors

  • "Can't change this state while flushing queries" → wrap the call in set_deferred() or call_deferred().
  • Collision not firing? Check the mask, not the layer. Then check the shape actually exists and has a non-zero size.
  • An Area2D with monitoring = false emits nothing. Setting it during a callback needs set_deferred.
  • Scaling a CollisionShape2D node distorts physics — resize the shape resource instead.
  • RigidBody positions must be changed through physics, not by assignment.
