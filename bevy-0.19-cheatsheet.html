00

Project setup

cargo

Bevy is a normal Rust crate. The only unusual parts are the compile-time profile tweaks and the assets/ folder, which must sit next to Cargo.toml.

Feature collections. Default features are 2d, 3d, ui, audio. As of 0.19 these are independent: ui is no longer pulled in by 2d/3d, and neither is audio. Trim what you don't need.

Faster iteration. Dynamic linking is the single biggest win; never ship with it.

Folder layout. asset_server.load("sprites/hero.png") resolves against assets/.

01

The app skeleton

bevy::app

An App is plugins + schedules + systems. Everything else is ECS data.

Built-in schedules, in run order.

ScheduleWhen it runs
PreStartup / Startup / PostStartupOnce, before the first frame.
FirstTop of every frame. Time is advanced here.
PreUpdateEngine input/window handling.
FixedFirst … FixedUpdate … FixedLastZero or more times per frame at a fixed rate. Put physics and anything rate-sensitive here.
UpdateYour game logic. Once per frame.
PostUpdateTransform propagation, visibility, culling.
LastCleanup. Window close/exit handling lives here as of 0.19.
OnEnter(S) / OnExit(S) / OnTransitionState changes. See States.

Group related systems into a plugin. This is the unit of reuse in Bevy — a plugin is just fn build(&self, app: &mut App).

System sets give you named ordering buckets across plugins.

Systems run in parallel by default. Two systems that mutably touch the same component are automatically serialized; you only need explicit ordering when the result matters.

02

ECS: components, queries, commands

bevy::ecs

Entities are IDs. Components are data. Systems are plain functions whose parameters declare what they touch.

Spawning and mutating. Commands is deferred: changes apply at the next sync point.

Queries. &T reads, &mut T writes, filters go in the second type parameter.

FilterMeaning
With<T> / Without<T>Archetype filter. Free — no per-entity check.
Changed<T> / Added<T>Change detection. Per-entity check.
Or<(With<A>, With<B>)>Combine filters.
Option<&T>In the data position, not the filter — matches whether or not T is present.
Has<T>Yields a bool instead of the data.

Hierarchy. Parent/child is a relationship built on the ChildOf component.

Custom relationships. Same machinery as parent/child, for any one-to-many link you want.

03

Resources, state, time

bevy::ecs · bevy::state

Globals go in resources. Coarse app modes go in states.

0.19 change: Resource is now a subtrait of Component — resources are stored as components on singleton entities. You can no longer derive both Component and Resource on one type. Split it into two types.

States drive menus, pause screens, and level loading.

Time and timers.

In FixedUpdate, Res<Time> is Time<Fixed> and delta_secs() is the constant fixed step. In Update it's Time<Virtual> — the frame delta, affected by pausing and time scaling.

04

Loading assets

bevy::asset

asset_server.load() returns a handle immediately and loads in the background. Paths are relative to assets/.

glTF / GLB models. Note the 0.19 rename: what used to be SceneRoot is now WorldAssetRoot, because bevy::scene was handed over to the new BSN scene system.

Creating assets in code and reading them back.

Dropping the last handle unloads the asset. Keep handles alive in a resource if you load things up front:
#[derive(Resource)] struct GameAssets { hero: Handle<Image> }

05

2D: sprites, text, shapes

bevy::sprite

Spawn a Camera2d first or you will stare at a blank window.

2D primitives you can hand to meshes.add(): Circle, Ellipse, Rectangle, Triangle2d, RegularPolygon, Annulus, Capsule2d, Rhombus, CircularSector.

Sprite sheets and animation.

Camera scaling: add Projection::from(OrthographicProjection { scaling_mode: ScalingMode::FixedVertical { viewport_height: 720. }, ..OrthographicProjection::default_2d() }) alongside Camera2d for a resolution-independent view.

06

3D: meshes, materials, lights

bevy::pbr

A mesh entity is Mesh3d + MeshMaterial3d + Transform. Nothing else is required.

0.19 change: the light field shadows_enabled is now shadow_maps_enabled, because lights also gained contact_shadows_enabled.

3D primitives: Cuboid, Sphere, Plane3d, Cylinder, Capsule3d, Cone, ConicalFrustum, Torus, Tetrahedron. Call .mesh() for a builder when you need subdivisions or UV modes.

Transforms.

A free-flying debug camera ships with the engine — useful before you write your own controller.

07

Input

bevy::input

Keyboard, mouse and gamepad state live in resources you poll each frame.

Screen position to world position.

Gamepads are entities, one per connected controller.

Run conditions keep input checks out of the system body.

08

Messages, events, observers

bevy::ecs::event

Since 0.17 these are two separate things. Messages are buffered and read on a schedule. Events are triggered and handled immediately by observers.

Messages — the old EventWriter/EventReader pattern, renamed.

Events + observers — reactive, run the instant they are triggered, and can trigger each other.

Entity events target a specific entity. Name a field entity: Entity and the derive wires up the target for you.

Lifecycle events fire automatically. Names: Add, Insert, Discard, Remove, Despawn.

0.19 change: the Replace lifecycle event is now Discard, and #[component(on_replace = ..)] is now #[component(on_discard = ..)]. Observers can also take .run_if(..) now.

Picking. Clicking meshes, sprites and UI nodes is built in — attach observers directly to the entity.

09

UI

bevy::ui

Bevy UI is flexbox. Node is the layout box; colour, borders and text are separate components on the same entity.

px(), percent(), vw(), vh() and auto() are prelude helpers that build Val. They also convert into UiRect, so padding: px(24).into() sets all four sides.

Two ways to react to a button.

Updating text. Text derefs to String.

0.19 change: TextFont::font_size is a FontSize enum (Px, Vw, Vh, VMin, VMax, Rem), and TextFont::font is a FontSource. Loading a font asset now needs .into():
TextFont { font: asset_server.load("f.ttf").into(), font_size: FontSize::Px(24.), ..default() }
You can also ask for FontSource::Monospace or FontSource::Family("Inter".into()) instead of shipping a file.

Text entry landed in 0.19.

bevy_ui_widgets (headless behaviour: sliders, checkboxes, scrollbars) and bevy_feathers (a styled, editor-flavoured widget set) are both in the box now. Feathers is aimed at tools, not shipped game UI.

10

Custom meshes from code

bevy::mesh

A Mesh is a topology, a set of vertex attributes, and optional indices. Build one, hand it to Assets<Mesh>, done.

AttributeFormat
Mesh::ATTRIBUTE_POSITIONVec<[f32; 3]>
Mesh::ATTRIBUTE_NORMALVec<[f32; 3]>
Mesh::ATTRIBUTE_UV_0Vec<[f32; 2]>
Mesh::ATTRIBUTE_COLORVec<[f32; 4]>, linear RGBA
Mesh::ATTRIBUTE_TANGENTVec<[f32; 4]>, needed for normal maps

Generating normals, and editing a mesh after the fact.

RenderAssetUsages::default() keeps a CPU copy and uploads to the GPU. Use RenderAssetUsages::RENDER_WORLD alone to drop the CPU copy and save memory — but then you can't read or mutate it later, and CPU picking against it stops working.

Custom vertex attributes need a matching MeshVertexAttribute constant with a unique ID, plus a specialized pipeline that declares the layout. That's the specialized_mesh_pipeline example, not a five-liner.

11

Your own WGSL shaders

bevy::shader

The shortest path to custom shading is a custom material: a struct that derives AsBindGroup and points at a .wgsl file in assets/.

The shader itself. Binding numbers match the #[uniform] / #[texture] / #[sampler] indices; the group is whatever Bevy assigns, so use the MATERIAL_BIND_GROUP shader def rather than hardcoding a number.

The 2D equivalent. Different trait, different plugin, different vertex-output import.

AsBindGroup attributeUse
#[uniform(0)] field: TT must implement ShaderType. Most glam and Bevy math types do.
#[texture(1)] #[sampler(2)]A Handle<Image> pair. Put both on the same field.
#[texture(1, dimension = "2d_array")]Array textures, cubemaps, 3D textures.
#[storage(3, read_only)]A Handle<ShaderBuffer> (renamed from ShaderStorageBuffer in 0.19).
#[bind_group_data(Key)]Data that feeds pipeline specialization, e.g. toggling shader defs.

Shader files hot-reload. Run with the file_watcher feature — cargo run --features bevy/file_watcher — and edits to .wgsl apply without a restart.

Bevy also accepts .wesl files, an extended WGSL with real modules and imports. The team plans to move engine shaders to it and endorse it as the default shading language, so it's worth knowing it exists.

Full-screen post-processing has a shortcut: implement FullscreenMaterial and place it in the pipeline with schedule_configs. For anything lower-level, render passes are now ordinary systems in the Core2d / Core3d schedules — the old RenderGraph node trait is gone as of 0.19.

12

Gizmos and debug tooling

bevy::gizmos · bevy::dev_tools

Immediate-mode debug drawing, redrawn every frame. Nothing to spawn or despawn.

Built-in overlays. These live behind the dev_tools feature — gate them so they never ship.

Logging. info!, warn!, error!, debug!, trace! are all in the prelude.

The 0.19 transform gizmo (TransformGizmoPlugin + TransformGizmoCamera + TransformGizmoFocus) gives you editor-style translate/rotate/scale handles. It deliberately ships without input wiring, so you connect it to your own controls.

13

BSN: the new scene system

bevy::scene

New in 0.19. bsn! is a declarative way to describe an entity and its children, with defaults, asset paths and observers inline. Optional, but it is where Bevy is heading.

Compare the two ways of writing the same thing. BSN fills in defaults, resolves "hero.png" into a Handle<Image> for you, and doesn't need the asset server threaded through.

Scenes compose. A bsn! block is a patch layered onto defaults, so you can extend one scene with another.

Tie a scene to a component so the whole thing always spawns together.

0.19 ships the code-driven half only. There is no .bsn asset loader yet, and glTF still loads through the old path (WorldAssetRoot). Both are planned for the next release.
