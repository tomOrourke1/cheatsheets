Impact sparks that land where you shoot

Build a one-shot GPUParticles3D burst in the editor, tune it in the inspector, then spawn it at the end of a raycast.

About 15 minutes, in GDScript, on the Forward+ or Mobile renderer.

  1. 1Build the emitter
  2. 2Node properties
  3. 3Process material
  4. 4Save as a scene
  5. 5Spawn on a hit
  6. 6Before you ship

A hit spark is the smallest useful particle effect in a 3D game: a dozen glowing shards that fire away from a wall for half a second and then delete themselves. It's also a complete tour of the particle workflow, because you have to get the emitter, the process material, the draw pass and the runtime spawning all working together.

Property names below match the inspector in Godot 4.7. Anything marked as new in 4.7 will be missing if you're on 4.6 or earlier — the effect still works, you just lose that dial.

Step 1Build the emitter

Make a new 3D scene with a GPUParticles3D as its root and name it ImpactSpark. Giving the effect its own scene is what lets you instantiate it later.

A fresh particle node draws nothing at all. Two properties bring it to life:

  1. Process Material — click the empty slot and choose New ParticleProcessMaterial. This resource computes particle motion on the GPU; it never draws anything itself.
  2. Draw Passes → Pass 1 — choose New QuadMesh, then click into it and set Size to 0.06 × 0.06. You get up to four passes, each with its own mesh and material, all driven by the same process material.

Now give the quad something to look like. Open the QuadMesh's Material slot, add a New StandardMaterial3D, and set:

QuadMesh → Material → StandardMaterial3D
TransparencyAlpha

Lets the alpha curve fade each shard out instead of popping.

Blend ModeAdd

Overlapping sparks build up to white. This is what makes them read as hot.

Shading ModeUnshaded

Sparks emit light, they don't receive it.

Billboard ModeParticle Billboard

Faces the camera and honours per-particle rotation, so you don't need Rotate Y.

Vertex Color → Use as AlbedoOn

Required, or the color ramp in the process material is ignored.

The viewport menu

With the particle node selected, a GPUParticles3D menu appears at the top of the 3D viewport. It holds Generate Visibility AABB, Create Emission Points From Node and the conversion to CPU particles. You'll want the first one at the end of this step.

Step 2Node properties: the timing

The node itself controls when particles exist. The material controls how they behave. Set these on the GPUParticles3D root:

GPUParticles3D
Amount24

Fixed particle budget. Changing it at runtime reallocates buffers and restarts the system, so pick a ceiling now.

Lifetime0.45

Seconds. Short is what sells an impact.

One ShotOn

Emit the whole batch once, then stop. Also what makes the finished signal fire.

Explosiveness1.0

At 0 the 24 particles trickle out across the lifetime; at 1 they all spawn on the same frame. A burst needs 1.

Randomness0.2

Jitters each particle's lifetime so they don't all wink out together.

Fixed FPS0

Defaults to 30, which visibly stutters on a fast burst. 0 means simulate every rendered frame.

Local CoordsOff

Off means particles are left behind in world space. If you ever parent the effect to something moving, this is the difference between sparks flying and sparks riding along.

Draw OrderLifetime

Irrelevant with additive blending; switch to View Depth if you move to alpha blending.

Transform AlignDisabled

Set to Y to Velocity if you'd rather have stretched streaks than round shards.

Visibility AABBgenerate

The culling box. Use the viewport menu once the effect looks right, or particles will vanish at certain camera angles.

EmittingOn for now

Leave it on while you tune so you can see the loop. Turn it off before saving — code switches it on.

Step 3Process material: the look

Click the ParticleProcessMaterial to open its property list. Most numeric properties come as a Min, a Max and a Curve. The rule is the same everywhere: each particle draws a random value between min and max when it spawns, and the curve then multiplies that value as the particle ages. Curves are where the effect stops looking mechanical.

Radius 0.02. A point emitter looks artificially clean; a tiny sphere gives the shards a believable origin spread.

Scale 3D / Angle 3D4.7

New in 4.7: per-axis scale and rotation ranges, so you can stretch shards along one axis only.

Also new in 4.7

ParticleProcessMaterial gained an Inherit Emitter Scale flag, and angular velocity was fixed to finally match its documented behaviour. If rotation speed looks different after upgrading a project, that fix is why.

Worth knowing about

  • Turbulence adds noise-driven drift. Lovely for smoke, distracting on sparks.
  • Collision set to Hide on Contact or Rigid lets shards bounce off GPUParticlesCollision3D shapes or an SDF of the level.
  • Sub Emitter points at a second particle scene — the classic use is a slow smoke puff spawned at the death of each spark.

Step 4Save it as a scene

Before saving to res://vfx/impact_spark.tscn, confirm three things, because each one causes a confusing bug later:

  • One Shot is on — otherwise finished never fires and the effect never frees itself.
  • Emitting is off — otherwise every instance fires the moment it's created, before you've positioned it.
  • Visibility AABB has been generated from the viewport menu.

Step 5Spawn it where the ray hits

Two pieces of information come back from a raycast, and you need both: the point tells you where to put the effect, the normal tells you which way is "out of the wall".

With a RayCast3D node

Best when the ray is always pointing the same way relative to the parent — a weapon muzzle, a sensor. It resolves once per physics frame on its own; force_raycast_update() forces an answer right now, which is what you want on a trigger press.

With a direct space query

Better for hitscan weapons, where the ray comes from wherever the camera happens to be looking and you want control over the exclusion list. Call it during physics processing.

The spawner

Three things happen here. The effect is added to the world rather than to the shooter, so it stays put. It's rotated so its -Z axis follows the surface normal, which is why Direction was set to 0, 0, -1 back in step 3. And it deletes itself when the last particle dies.

Why the signal, not a timer

finished fires when every active particle has finished processing, which accounts for lifetime, randomness and explosiveness together. A hand-tuned await get_tree().create_timer(...) goes stale the moment you change any of those. The signal only exists on one-shot emitters.

If you fire fast: one emitter, many bursts

Instantiating a scene per shot is fine for a pistol and wasteful for a minigun. The alternative is a single long-lived emitter with Emitting off and a generous Amount, injecting particles by hand:

emit_particle() has a renderer requirement

It works on Forward+ and Mobile only — on the Compatibility renderer the call does nothing, silently. If you're targeting older mobile hardware or the web, stick with instantiated one-shot scenes.

Step 6Before you ship it

  • Particles disappear at some camera angles. Regenerate the Visibility AABB — you almost certainly widened the burst after generating it the first time.
  • The burst drags behind a moving target. Either Local Coords is on, or you parented the effect to something that moves. Add it to the world instead.
  • Restarting a one-shot mid-flight. Setting emitting = true again can be ignored for a frame or two on the GPU. Call restart() instead when you need an immediate re-fire.
  • Deterministic playback. Turning on Use Fixed Seed, or calling restart(true) to keep the seed, makes a burst repeat identically — handy for cutscenes and for request_particles_process() when scrubbing.
  • Test in the exported build. Particle timing differs between the renderers, and Compatibility silently drops several process material features.

Once the spark scene exists, the same spawner handles every surface type: keep the code identical and swap the scene based on what get_collider() returns — dust for concrete, splinters for wood, a ripple decal for water.
