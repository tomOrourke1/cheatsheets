What you're building

Bevy is an ECS engine: everything in the world is an entity, entities are bags of components, and all behaviour lives in plain functions called systems. This guide leans on that directly — each step is one more component or one more system, and you can run the project after every one of them.

The code targets Bevy 0.19. Bevy's API changes between releases, so if you are on an older version, start from its migration guide rather than expecting this to compile as-is.

Create the project

Open Cargo.toml and replace it with this. The two profile sections matter more than they look: without them, Bevy runs its own rendering and math code unoptimised and you get a slideshow.

Watch out

The very first cargo build compiles all of Bevy and takes several minutes. Every build after that is incremental and quick. If link times bother you, cargo run --features bevy/dynamic_linking links Bevy as a shared library during development.

Step 03

Open a window

Replace src/main.rs with the smallest Bevy app there is. DefaultPlugins brings in the window, the renderer, input, assets and the game loop.

Checkpoint

A grey window opens and stays open. Nothing is drawn yet because there is no camera and nothing to look at.

Step 04

Build the scene

Now fill the world. A Startup system runs once, and commands.spawn creates an entity from a tuple of components. Three things make an object visible: a mesh, a material, and a transform.

Bevy is Y-up. The ground sits at y = 0, so a sphere of radius 0.5 rests at y = 0.5.

Checkpoint

An orange ball on a grey floor, four blocks scattered around it, lit from one side with soft shadows. The camera is fixed; nothing moves yet.

Note

Meshes and materials are assets, not components. You add them to Assets<Mesh> / Assets<StandardMaterial> and the entity holds a cheap handle, which is why the blocks can share one mesh and one material with .clone().

Step 06

Capture the mouse

Mouse look needs the pointer locked to the window, otherwise it walks off the edge of the screen and clicks on your browser. Lock it on click, release it on Esc — the same contract every desktop game uses.

Register it. Single is a system parameter that grabs the one matching entity, and quietly skips the system if there isn't exactly one.

Watch out

Windows has no true locked mode and falls back to confining the cursor to the window; macOS is the other way around. Both feel the same in practice, but don't be surprised if the pointer is still technically movable.

Step 07

Look around

Read the frame's pooled mouse movement from AccumulatedMouseMotion and fold it into the rig's angles. Yaw turns freely; pitch is clamped just short of straight up and straight down, because a camera that flips over its own pole is a bug report waiting to happen.

Nothing on screen changes yet — you are only editing two numbers. The next step spends them.

Step 08

Put the camera behind the ball

This is the whole third-person camera: take a point above the ball, push the camera straight backwards from it, then rotate that offset by yaw and pitch. Because the camera is a separate entity rather than a child of the ball, the ball can spin however it likes without dragging the view around with it.

Step 09

Walk with WASD

Movement should follow the camera, not the world axes: pressing W means "away from me", whichever way you are facing. So take the rig's yaw, flatten it onto the ground plane, and build forward and right vectors from it.

Everything is multiplied by time.delta_secs(), the length of the last frame. Skip that and your ball moves faster on a faster machine.

Add move_player to the chain, between orbit_camera and follow_player.

Note

Normalising the direction is what stops diagonals being about 1.4× faster than straight lines — the classic bug in every first movement system.

Note

The compiler will warn that player is unused until the next step fills that gap. Expected.

Step 10

Jump

A jump is one number. Pressing Space sets an upward velocity, gravity pulls that number down every frame, and the floor catches it. Replace the placeholder comment in move_player with this:

just_pressed fires on the frame the key goes down, so holding Space does not pogo. The grounded flag is what stops mid-air double jumps.

Checkpoint

Click, move with WASD, press Space. The ball arcs up, comes down, and lands cleanly. Try jumping while running — the horizontal step keeps applying in the air, which is what you want.

Note

Want a floatier jump? Raise JUMP_SPEED and lower GRAVITY together. Real games tune these by feel, not by physics.

Step 11

Make it roll

A sliding sphere looks dead. A rolling one reads as a physical object, and it costs four lines: spin around the axis perpendicular to travel, by the arc length just covered. Add this at the end of move_player.

Dividing distance by radius converts a distance along the ground into radians of rotation, which is why the ball never appears to skid.

Note

The rotation is cosmetic here — nothing reads the ball's orientation. Give it a striped or textured material and the effect is much more obvious.

Where to go next

  • Real collisions

    Right now the floor is a single if. Swap in a physics crate such as Avian or Rapier and the ball gets slopes, ramps and bouncing for free. Check crates.io for the release that matches Bevy 0.19.

  • Coyote time

    Keep a short timer after the ball leaves the ground and let a jump still fire during it. Two lines, and jumps stop feeling like they were eaten.

  • Camera collision

    Cast a ray from the ball to the camera and pull the camera in when a wall is in the way, instead of clipping through it.

  • Rebindable input

    Move the key checks behind a resource so players can remap them, or reach for an input-mapping crate once the list grows.

  • Scenes with BSN

    Bevy 0.19 introduced the bsn! macro for declaring entities. Your setup function is exactly the sort of code it is designed to shrink.

  • Read the examples

    The Bevy repo ships runnable examples for almost every feature. Clone it, check out the 0.19 tag, and cargo run --example 3d_scene.
